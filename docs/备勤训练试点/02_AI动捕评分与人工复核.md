# 备勤训练试点 AI 动捕评分与人工复核

## 1. 输入边界

首期评分输入为 `pre_recorded_desensitized_sample`（预录脱敏片段）。训练工作台可在浏览器本地调用摄像头进行实时录像，录像仅用于现场回放，不上传服务端、不做身份识别；结束后仍使用本试点确定性规则评分，用于验证字段、流程和复核责任链，不代表实时动捕模型已接入生产环境。摄像头不可用时，可用 `Tab + P` 或“快捷评分”按钮触发同一评分链路。

## 2. 评分结构

评分返回三个分项和一个总分：

| 字段 | 权重 | 说明 |
|---|---:|---|
| `standardization` | 40% | 动作规范度样例分 |
| `completionTime` | 35% | 相对达标用时的样例分 |
| `coordination` | 25% | 协同一致性样例分 |
| `total` | 100% | 加权总分，四舍五入 |

用时分按 `max(0, min(100, 100 - max(0, elapsed - threshold) * 5))` 计算；本规则是确定性试点评分，不是模型精度承诺。

## 3. 必须留痕的结果字段

```ts
type ReadinessAssessment = {
  assessmentId: string;
  taskId: string;
  inputMode: 'pre_recorded_desensitized_sample' | 'real_time_authorized_feed';
  score: { standardization: number; completionTime: number; coordination: number; total: number };
  confidence: number;
  evidence: string[];
  evidenceTime: string;
  ruleVersion: string;
  humanReviewRequired: true;
  reviewStatus: 'pending' | 'confirmed' | 'revised' | 'rejected';
  reviewerId?: string;
  reviewComment?: string;
  auditId: string;
};
```

缺少证据、时间、规则版本、人工复核标识或审计编号时，结果只能停留在“待复核”，不得进入档案。

## 4. 教官复核

- `confirmed`：接受样例评分，生成训练档案。
- `revised`：接受教官修订后的结果，生成训练档案并保留修订原因。
- `rejected`：驳回评分，任务转为 `待复训`，不得生成正式档案。

复核接口必须携带 `decision`、`reason`、`reviewerId`。AI 不得直接改变合格结论、人员状态或勤务业务状态。

## 5. 档案与补训

复核确认后生成 `TrainingArchive`，至少包括任务、评分、学员、班组、结果、薄弱项、补训建议和档案审计编号。首期默认建议 7 日内完成针对性补训。档案页可显式创建一条 `待训练` 补训任务，继承原科目、装备和达标值，并在 `basis` 中记录 `来源档案 {recordId}`；不因 AI 建议自动创建或直接下达任务。

## 6. 播报与降级

- 评分完成后，页面生成“小安评价”文字，并尝试调用浏览器 `SpeechSynthesis` 播报；浏览器不支持或播报失败时保留文字，不影响复核。
- `Tab + P` 仅作为设备异常/无摄像头时的人工快捷触发，不绕过任务状态、评分接口或人工复核。
- 本地录像采用 `MediaRecorder` 生成临时回放地址，页面离开或重新训练时释放媒体轨道与对象 URL。
