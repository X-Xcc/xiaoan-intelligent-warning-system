# 公安大数据与 AI 平台｜备勤训练试点总控与排期

> 版本：V1.0  
> 生效日期：2026-09-06  
> 试点执行周期：2026-09-07 至 2026-10-04（4 周）  
> 适用范围：备勤训练试点；只覆盖 A1、A2、A3 和训练档案。

## 1. 试点目标、边界与完成定义

### 1.1 唯一目标

在一个可控班组内跑通“勤务态势驱动训练推荐 -> 训练任务执行 -> AI 动捕评分与教官复核 -> 训练档案沉淀 -> 补训建议”的完整闭环，证明训练安排、过程记录和结果反馈可以被同一平台连续支撑。

### 1.2 范围内

| 编号 | 能力 | 必须交付的最小闭环 |
|---|---|---|
| A1 | 勤务态势 | 读取脱敏样例勤务数据，显示风险画像、数据更新时间、规则版本和至少 3 条训练推荐依据。 |
| A2 | 靶向训练 | 创建、分配、开始、完成和异常登记训练任务；每个任务包含对象、科目、装备、达标值、用时和确认人。 |
| A3 | AI 动捕考核 | 对预录或实时动作片段输出规范度、完成用时、协同一致性、总分和置信度；教官可确认或修订。 |
| T1 | 训练档案 | 按个人、班组和科目保存任务、过程、评分、复核、补训记录，并形成薄弱项与下一轮建议。 |

### 1.3 明确不做

- 不接入真实生产警情全量数据；首期只使用经批准的脱敏样例数据。
- 不进入接处警、案件研判、视频图侦、GIS 推演、抓捕调度和跨警种协同。
- 不从零训练动作识别基础模型；优先对接成熟动捕/姿态能力或使用预录样例。
- AI 不直接作出合格、派警、处罚、档案定级等最终业务决定；最终判定必须由授权教官确认。

### 1.4 完成定义（DoD）

试点完成必须同时满足以下四项，不能以单页演示替代闭环：

1. 更换一组脱敏样例数据后，A1 的训练推荐及其依据随规则变化。
2. 一个班组可在 A2 完成 3 个训练科目的领取、开训、完成和异常登记。
3. 至少 3 个训练样例可在 A3 完成评分、回看、人工确认或修订。
4. 训练结果可进入 T1 档案，并由档案创建一次可追溯的补训任务。

## 2. 固定闭环、数据边界与责任链

```text
脱敏勤务样例 + 规则版本
          ↓
A1 风险画像 / 训练建议依据
          ↓
A2 训练任务 / 人员班组 / 达标标准 / 过程记录
          ↓
A3 动捕评分 / 置信度 / 复核 / 审计编号
          ↓
T1 个人与班组训练档案 / 薄弱项 / 补训建议
          └───────────────────────────────→ A2 下一轮任务
```

### 2.1 统一业务对象

| 对象 | 主键建议 | 必填字段 | 产生方 | 消费方 |
|---|---|---|---|---|
| 态势快照 | `situationSnapshotId` | 数据时间、规则版本、风险标签、推荐依据 | P1 | A1、A2 |
| 训练任务 | `trainingTaskId` | 科目、班组/人员、装备、达标值、状态、确认人 | P3 | A2、T1 |
| 动作评分 | `assessmentId` | 三项分值、总分、置信度、片段引用、复核状态、审计编号 | P2 | A3、T1 |
| 训练档案 | `trainingRecordId` | 任务引用、队员/班组、过程、评分引用、补训建议 | P4 | T1、A2 |

### 2.2 AI 结果最低责任链

所有 A3 评分结果必须按以下字段保存与展示；缺任一字段不得进入正式训练档案：

```ts
type ReadinessAssessment = {
  assessmentId: string;
  taskId: string;
  score: {
    standardization: number;
    completionTime: number;
    coordination: number;
    total: number;
  };
  confidence: number;
  evidenceRef: string[];
  evidenceTime: string;
  ruleVersion: string;
  humanReviewRequired: true;
  reviewStatus: 'pending' | 'confirmed' | 'revised' | 'rejected';
  reviewerId?: string;
  reviewComment?: string;
  auditId: string;
};
```

## 3. 工作包、接口和依赖关系

所有工作包于第 1 周并行启动；P1 在第 1 周结束前冻结数据和规则契约，P2/P3/P4 可基于该契约继续联调。任何工作包不得绕过总控自行扩大范围。

| 包 | 名称 | 责任角色 | 允许交付范围 | 前置依赖 | 向外冻结的输出 |
|---|---|---|---|---|---|
| P1 | 训练数据与规则 | 业务教官、数据人员 | 脱敏样例、风险标签、态势快照、科目映射、达标标准 | 无 | `SituationSnapshot`、规则表、数据字典 V1 |
| P2 | AI 动捕与评分 | AI 工程师、训练教官 | 片段接入、评分引擎、置信度、人工复核、评测样本 | P1 的科目和达标规则 | `ReadinessAssessment`、评分说明 V1 |
| P3 | A1-A3 工作台 | 产品负责人、前端工程师 | A1/A2/A3 页面、演示控制台、任务操作、静态备份 | P1 数据契约；P2 评分契约 | 页面行为、接口映射、演示脚本 V1 |
| P4 | 档案、集成与保障 | 后端工程师、测试运维 | 训练档案、权限、审计、备份、联排、验收记录 | P1/P2/P3 的对象契约 | `TrainingRecord`、权限日志、运行手册 |

## 6. 责任分工与会议节奏

### 6.1 RACI

| 事项 | 项目负责人 | 训练教官 | 数据人员 | AI 工程师 | 产品/前端 | 后端/测试运维 | 班组长 |
|---|---|---|---|---|---|---|---|
| 试点范围与变更批准 | A | C | C | C | C | C | I |
| 科目、装备、达标值、评分权重 | I | A/R | C | R | I | I | C |
| 脱敏数据与态势规则 | I | C | A/R | C | I | C | I |
| A1-A3 产品实现 | I | C | C | C | A/R | C | I |
| 评分服务与复核能力 | I | A/C | I | R | C | C | I |
| 训练档案、权限、审计、备份 | I | C | C | C | C | A/R | I |
| 试点训练执行与验收 | A | R | I | C | C | C | R |

注：R=执行，A=最终负责，C=协商，I=知会。每个事项只允许一个 A。

### 6.2 固定节奏

| 节奏 | 参与者 | 产出 | 时长 |
|---|---|---|---|

| 周五闸门会 | 项目负责人、各验收人 | 本周验收记录、下周冻结项、变更决定 | 30 分钟 |

## 7. 变更规则与质量约束

### 7.1 变更分级

| 等级 | 例子 | 决策人 | 时限 | 处理规则 |
|---|---|---|---|---|
| S0 阻断 | 无法脱敏、评分不能复核、档案无法入库、权限越权 | 项目负责人 | 当日 | 暂停受影响链路；先修复并复测，不以演示替代。 |
| S1 契约 | 改字段、状态枚举、主键、达标值、评分权重 | 项目负责人 + 训练教官 | 1 个工作日 | 更新数据字典/规则版本/测试样例；P1-P4 全部确认。 |
| S2 范围 | 增加新科目、新页面、新数据源、新业务场景 | 项目负责人 | 周五闸门会 | 只进入第二期候选池；本期默认不接收。 |
| S3 展示 | 文案、色彩、布局、非关键排序 | 产品负责人 | 1 个工作日 | 不影响接口、规则和验收脚本时可实施；须记录。 |

### 7.2 变更单最小字段

每项 S0-S3 变更必须在变更记录中写明：`编号`、`提出日期`、`提出人`、`影响页面/对象`、`影响工作包`、`变更前后`、`风险`、`决定人`、`测试证据`、`关闭日期`。未记录的口头变更一律无效。

### 7.3 数据、AI 与安全红线

- 试点数据不得包含真实身份证号、完整报警录音、案件全文、真实人脸原始素材或模型密钥。
- 页面必须显示数据更新时间与规则版本；评分必须显示置信度、证据引用、复核状态和审计编号。
- 教官的确认、修订、驳回和补训创建均需写入不可抵赖的操作日志。
- 未获授权的用户不可查看其他班组训练档案；导出功能首期默认关闭。
- 演示备用页使用同一冻结数据快照，严禁与运行页口径不一致。


## 11. 启动日行动清单（2026-09-07）

1. 项目负责人确认试点班组、三项训练科目、参与人员与验收人。
2. 训练教官确认每个科目的装备清单、达标值、评分权重和复核规则。
3. 数据人员交付第一版脱敏样例及字段说明；数据源只保留试点必要字段。
4. AI 工程师确认预录视频、实时摄像头或现有动捕设备三选一的接入方案，并准备失败回退到预录片段。
5. 产品/前端与后端/测试运维按本文件建立 P1-P4 工作包看板，登记接口契约与测试证据。

本文件是试点唯一总控口径。与其他需求、展示稿或口头意见发生冲突时，以“范围不扩张、闭环可验证、AI 可复核、训练档案可追溯”为优先判断原则，并按第 7 节办理变更。
