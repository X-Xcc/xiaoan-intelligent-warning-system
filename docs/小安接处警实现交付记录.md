## 2. 如何运行

当前本机隔离工作台：`http://127.0.0.1:5188/command`。默认只读教学回放。

隔离接口：`http://127.0.0.1:8021/api`。数据库固定在 `tmp/command-demo/command.sqlite3`；材料固定在 `tmp/command-demo/evidence/`，不会使用 `server/.env` 中的业务数据库。

重新启动：

```powershell
# 终端1：仅本机隔离后端
Set-Location -LiteralPath 'D:\CICSIC'
& '.\server\.venv-runtime\Scripts\python.exe' scripts/serve_command_demo.py --port 8021

# 终端2：专用联调配置，不修改正式后端地址
Set-Location -LiteralPath 'D:\CICSIC\apps\dashboard'
& '..\..\node_modules\.bin\vite.cmd' --config vite.command.config.ts
```

停止时关闭对应开发终端或按Ctrl+C；后台启动的服务按启动记录中的PID停止，只停止本次联调进程。端口已占用时不要结束不明进程。修改后端端口时同步修改 `vite.command.config.ts` 中的隔离API地址。

教学账号入口只存在于 `serve_command_demo.py` 创建的本机应用；正式 `app.main` 不提供匿名教学登录接口。账号凭据在启动时随机生成，重启后需要重新选择教学账号登录。

### 联调顺序

1. 打开工作台，选择“业务联调”。
2. 选择“接警员”并登录，点击“新建教学轮次”；记下事件编号。
3. B1确认警情摘要。修订接警文本或地点后，需要重新确认。
4. 登录“指挥席”，选同一事件；B2预览路线，确认分级派警建议，再下达派警。
5. 登录“处警人员”，选同一事件，依次接收任务、确认到场、开始处置。这是Web联调入口，不代替微信端实测。
6. B3查询“陈XX”或“教学档案-03”；执行人工确认、登记无匹配，或填写原因转人工。
7. B4登记文字材料；也可从 `apps/dashboard/public/command/` 选择教学图片上传。上传成功且登记成功后才进入证据索引。
8. 填写移交摘要并提交。登录“研判人员”，选同一事件，进入“移交”接收或退回。
9. 研判接收后，处警人员填写现场结果并完成任务。
10. 刷新核对事件状态、材料、移交和审计记录。切回“只读教学回放”及复位画面，不会删除或再次派单。

工作人员映射为数据库中的 `staffId=wang`、显示名“王队”。教学名称“135快反组”不是独立多人派警模型。

## 3. 核心实现

### 事件与事务

- 仍使用现有 `SafetyEvent` 主记录与公共状态枚举。
- 接处警进度、版本、原文历史、核验记录、证据索引与移交历史写入 `meta.command`。
- 摘要确认和派警建议确认分开；GET路线预览只读。
- 派单、负责人、接处警进度、审计和幂等回执在同一数据库事务提交。
- 写入使用 `expectedVersion`；PostgreSQL行锁与进程锁保护当前记录。隔离SQLite并发测试覆盖同进程竞争，不能据此宣称多实例PostgreSQL压测已通过。
- `requestId`回执持久化；相同内容重试返回原回执，不同内容冲突。
- `GET /api/command/events/{eventId}/receipts/{requestId}`用于核对超时请求。
- WebSocket仅发送事件变更提示，逐连接验证当前token和事件访问权；页面保留轮询恢复，不宣称消息已经到达设备。

### 责任与资料

- 新增显式 `CommandPrincipal` 授权，不根据用户名或openid前缀猜测接处警权限。
- `intake / dispatch / field / analyze / display / audit`是模块权限；现场写入额外要求警力映射与事件负责人匹配。
- 旧状态、派单、路线、补充和视觉审核入口不能绕过接处警守卫。
- 普通事件列表和公共事件服务默认不返回接处警资料；旧详情入口按授权读取。
- 接处警材料必须携带当前事件ID上传；登记依赖服务端上传回执，不接受任意URL。
- 文件有上传者、事件归属和内容摘要；索引同步写入三处现有/新增字段。
- 提交及接收移交均复核文件存在和摘要；跨事件材料、缺失文件、伪造回执被拒绝。
- 移交待审时冻结材料，退回保留上一版；接收不更改公共状态，现场完成另走人工动作。

### 界面与回放

- `/command`为原有入口；从大文件迁出实际实现，保留兼容导出。
- 工作台采用项目现有Ant Design；蓝色大屏样式只在展示面生效。
- `surface=display`隐藏工作台导航、表单和控屏按钮。
- `BroadcastChannel`只同步展示阶段、轮次和事件引用，不广播核验或材料正文；业务大屏自行按账号读取。
- 只读回放使用同一冻结场景，绝不自动调用派警、复核、上传或移交接口。
- 切换事件或账号清空旧表单/快照；晚到响应按事件、请求序列和版本丢弃。
- 业务断线保留当前会话中的最后快照，明确显示离线；教学备用页需显式切换。
- 素材全部标识教学来源。真实事件的B4展示当前授权文件，不替换为剧情图片。

## 4. 数据结构变更与回退

新增三张表，由现有SQLAlchemy建表机制创建：

| 表 | 用途 | 生产接入注意事项 |
|---|---|---|
| `command_principals` | 显式账号权限、工作人员映射 | 必须由授权运维配置，不允许客户端自报 |
| `command_receipts` | 事件/创建范围的幂等回执 | 与业务写入同事务，不应单独清空 |
| `command_uploads` | 材料上传回执、归属、摘要 | 需与文件目录共同备份 |

没有改变既有事件主键或公共状态枚举。接处警事件的旧写入口现在拒绝无版本的修改，移动端已增加版本化调用；其他模块的旧事件行为由核心事件测试回归。

若需要回退页面，可恢复旧路由引用，但**不要解除后端接处警守卫**来让旧页面写入新事件。保留三张表、`meta.command`与证据目录，暂停新模块业务写操作；不要删除审计或强行把已接收移交改回草稿。正式环境上线前另做数据库备份和迁移演练。
