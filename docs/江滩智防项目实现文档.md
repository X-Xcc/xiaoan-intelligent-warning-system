文档属性：项目主实现文档

## 1. 项目定位

江滩智防是一套面向开放式滨水区域的便民服务与安全治理系统原型，核心场景是“两滩七湾”区域的开放状态查询、附近服务导航、隐患上报、游客求助、工作人员处置和 Web 指挥舱展示。

第一版目标不是做完整政务平台，而是做出可演示、可运行、链路闭环的系统：游客查看便民信息、上报隐患或发起求助，后端生成险情事件和处置任务，工作人员接收并流转任务，Web 指挥舱实时展示态势。

## 3. 产品原则

- 首页先展示开放状态和便民服务，不把紧急求助作为首屏主入口。
- 紧急求助先电话报警，再补充定位和现场信息，避免把小程序误当成报警替代。
- 隐患上报采用分步填写，提交后可追踪处理进度。
- 工作人员端突出任务优先级、位置、状态流转和处置留痕。
- Web 指挥舱突出实时态势、预警、工单和统计，适合比赛展示。
- AI 功能可降级：真实识别不稳定时，仍可通过模拟预警完成演示。

## 5. 三端功能范围

### 5.1 游客端小程序

底部导航：`首页 | 上报 | 求助 | 进度 | 我的`。

首页展示当前湾区开放状态、水位、客流、地图、附近服务和游玩提醒，并提供“隐患上报”等便民入口。

紧急求助页采用独立应急页：先明确提示报警优先，提供 `110` / `120` 直拨按钮，再提供“同步给江滩工作人员”入口。状态页展示“位置已同步、工作人员正在赶来、当前进度、预计响应”，并引导补充现场信息。

安全上报用于非紧急隐患，字段包括问题类型、位置、照片、描述、是否匿名。提交后进入进度追踪。

进度页按全部、求助、隐患、失物筛选，详情页使用时间轴展示已提交、已受理、已派单、已到达、已完成、已归档。

### 5.2 工作人员端小程序

工作人员登录后进入巡防工作台，查看今日任务、待处理、处理中和在线状态。

任务卡片展示险情等级、类型、湾区、来源、距离、处置时限和当前状态。任务流转为：待接收 -> 已接收 -> 已到达 -> 处理中 -> 已完成 -> 已归档。

任务详情包含事件描述、现场图片、位置、来源、处置时间轴和反馈入口。完成处置时填写处置结果、现场照片和是否解除风险。

### 5.3 Web 指挥舱

指挥舱页面结构为顶部状态栏、左侧态势指标、中间概念化两滩七湾地图、右侧实时险情和待处置任务、底部统计图表。

管理端提供事件工单、人员、设备、物资和预案等模块入口。事件工单数据从后端读取，后台操作包括登记现场求助、派单首单、闭环首单和刷新数据，不再使用前端本地假工单。

## 6. 数据与接口

当前已落地数据表：`safety_events`，开发期存储在 `server/data/jiangtan.db`。它统一承载求助、隐患上报、失物认领、工作人员流转和后台闭环。

后续生产化扩展表：`users`、`visitor_profiles`、`staff_profiles`、`bay_areas`、`risk_events`、`user_reports`、`work_orders`、`event_logs`、`lost_found`。

关键接口：

```text
GET    /api/events
GET    /api/events/overview
POST   /api/events/help
POST   /api/events/reports
POST   /api/events/lost-claims
PATCH  /api/events/{event_id}/status
PATCH  /api/events/{event_id}/supplement
```

待生产化接口：

```text
POST /api/auth/wechat-login
POST /api/auth/staff-login
GET  /api/auth/me
WS   /ws/alerts
```

## 7. 术语约定

游客端用语保持温和服务化，使用“便民服务、隐患上报、紧急求助、处理进度、工作人员正在赶往现场”。工作人员端和 Web 指挥舱可使用更专业的“险情、处置任务、巡防力量、风险研判、处置闭环”。

避免在游客端使用“警情、出警、派警、案件、布控”等强执法词汇。
