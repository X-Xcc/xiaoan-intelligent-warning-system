# 江滩智防项目实现文档

版本：V1.2  
日期：2026-07-31  
定位：微信小程序真实移动端 + Web 指挥舱展示端 + FastAPI 统一后端  
文档属性：项目主实现文档

## 1. 项目定位

江滩智防是一套面向开放式滨水区域的安全治理系统原型，核心场景是“两滩七湾”区域的游客求助、隐患上报、工作人员处置和 Web 指挥舱展示。

第一版目标不是做完整政务平台，而是做出可演示、可运行、链路闭环的系统：游客发起求助或上报，后端生成险情事件和处置任务，工作人员接收并流转任务，Web 指挥舱实时展示态势。

## 3. 产品原则

- 首页先展示安全状态和求助入口，不做功能堆叠。
- 紧急求助先发送定位和事件，再补充详情，避免表单阻断。
- 隐患上报采用分步填写，提交后可追踪处理进度。
- 工作人员端突出任务优先级、位置、状态流转和处置留痕。
- Web 指挥舱突出实时态势、预警、工单和统计，适合比赛展示。
- AI 功能可降级：真实识别不稳定时，仍可通过模拟预警完成演示。

## 5. 三端功能范围

### 5.1 游客端小程序

底部导航：`首页 | 上报 | 求助 | 进度 | 我的`。

首页展示当前湾区、安全状态、水位、客流、今日提示，并提供“一键求助”和“安全上报”入口。

紧急求助页采用极简长按按钮：长按 2 秒发送定位，立即创建高风险险情事件，并进入求助状态页。状态页展示“求助已发送、工作人员正在赶往现场、当前进度、预计响应”，并引导补充现场信息。

安全上报用于非紧急隐患，字段包括问题类型、位置、照片、描述、是否匿名。提交后进入进度追踪。

进度页按全部、求助、隐患、失物筛选，详情页使用时间轴展示已提交、已受理、已派单、已到达、已完成、已归档。

### 5.2 工作人员端小程序

工作人员登录后进入巡防工作台，查看今日任务、待处理、处理中和在线状态。

任务卡片展示险情等级、类型、湾区、来源、距离、处置时限和当前状态。任务流转为：待接收 -> 已接收 -> 已到达 -> 处理中 -> 已完成 -> 已归档。

任务详情包含事件描述、现场图片、位置、来源、处置时间轴和反馈入口。完成处置时填写处置结果、现场照片和是否解除风险。

### 5.3 Web 指挥舱

V0.1 只做一个全屏页面，不做复杂后台侧边栏。页面结构为顶部状态栏、左侧态势指标、中间概念化两滩七湾地图、右侧实时险情和待处置任务、底部统计图表。

演示模式默认收起，展开后提供模拟 AI 预警、模拟游客求助、模拟接单、完成处置和重置数据。

## 6. 数据与接口

核心数据表：`users`、`visitor_profiles`、`staff_profiles`、`bay_areas`、`risk_events`、`user_reports`、`work_orders`、`event_logs`、`lost_found`。

关键接口：

```text
POST /api/auth/wechat-login
POST /api/auth/staff-login
GET  /api/auth/me
POST /api/emergency/help
PATCH /api/events/{event_id}/supplement
POST /api/reports
GET  /api/reports/my
GET  /api/events
POST /api/work-orders
PATCH /api/work-orders/{id}/accept
PATCH /api/work-orders/{id}/arrive
PATCH /api/work-orders/{id}/complete
WS   /ws/alerts
```

## 7. 术语约定

游客端用语保持温和服务化，使用“一键求助、安全上报、处理进度、工作人员正在赶往现场”。工作人员端和 Web 指挥舱可使用更专业的“险情、处置任务、巡防力量、风险研判、处置闭环”。

避免在游客端使用“警情、出警、派警、案件、布控”等强执法词汇。
