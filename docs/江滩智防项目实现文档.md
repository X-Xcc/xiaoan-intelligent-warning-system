## 3. 产品原则

江滩智防不是单纯的炫酷页面，也不是普通的信息登记小程序，而是一套面向开放式滨水区域的安全治理系统原型。

核心原则：

- 首页看安全：游客一打开就知道当前区域是否开放、风险如何、哪里可以求助。
- 报警先发送：紧急求助页面不堆表单，先发送定位和事件，再补充信息。
- 上报分步填：隐患上报像成熟互联网产品一样分步引导，避免一屏塞满输入框。
- 进度可追踪：上报后要像快递物流一样显示处理状态，体现闭环治理。
- 指挥舱可展示：Web 大屏负责比赛现场的视觉冲击和管理价值表达。
- 系统可降级：AI 不稳定时，仍可通过模拟预警和游客上报完成演示。

## 6. 小程序登录方案

小程序启动后首先进入统一登录页。

页面结构：

```text
标题：江滩智防
副标题：两滩七湾滨水安全治理平台

主按钮：微信一键登录
次入口：工作人员登录
```

游客登录：

- 点击“微信一键登录”。
- 小程序调用 `wx.login()` 获取 `code`。
- 调用后端 `POST /api/auth/wechat-login`。
- 后端通过微信 `code2Session` 获取 `openid`。
- 后端查找或创建游客用户，返回系统 `token`。
- 游客进入游客端首页。

工作人员登录：

- 点击“工作人员登录”。
- 进入工号密码登录页。
- 输入工号和密码。
- 调用 `POST /api/auth/staff-login`。
- 后端校验成功后返回 `token`、`staff_id`、姓名和岗位。
- 进入工作人员端工作台。

手机号策略：

- 第一版游客登录不强制绑定手机号。
- 提交紧急求助或隐患上报时，引导填写联系电话。
- 后续可加入微信手机号授权，但不作为第一阶段强依赖。

## 7. 游客端页面规划

底部导航建议：

```text
首页 | 上报 | 求助 | 进度 | 我的
```

其中“求助”为中间凸起按钮，始终醒目，任何页面都能快速进入报警页。

### 6.1 游客首页

首页目标：让游客快速判断当前区域是否安全，并能迅速进入求助或上报。

建议结构：

```text
顶部：
  江滩智防
  当前定位：3号湾区附近

安全状态卡：
  当前开放：开放中
  风险等级：低 / 中 / 高
  水位：正常
  客流：适中

主入口：
  一键求助
  隐患上报

服务入口：
  湾区状态
  救援点
  失物招领
  安全须知

底部：
  今日安全提示
```

设计建议：

- 不要堆太多功能入口。
- 第一屏优先展示安全状态和求助入口。
- 风格参考大厂生活服务类小程序，清爽、可信、操作路径短。

### 6.2 紧急求助页

该页面参考用户草图：中间一个超大圆形报警按钮，页面极简。

页面结构：

```text
顶部：
  紧急求助
  已定位：3号湾区附近

中间：
  超大圆形按钮
  文案：按住求助
  副文案：长按2秒发送当前位置

底部：
  非紧急情况？前往隐患上报
```

状态设计：

| 状态 | 页面表现 |
|---|---|
| 默认 | 蓝绿色安全光环，显示“按住求助” |
| 长按中 | 橙色进度环，显示“正在确认，请继续按住” |
| 已发送 | 绿色成功态，显示“求助已发送” |
| 失败 | 红色提示，显示“发送失败，请重试” |

交互流程：

```text
进入紧急求助页
  ↓
长按中间圆形按钮 2 秒
  ↓
立即创建高风险求助事件
  ↓
Web 指挥舱出现红色预警
  ↓
工作人员端收到待处理任务
  ↓
游客进入补充信息页
```

重要原则：

- 报警页不做复杂表单。
- 先发送定位和事件，再补充详细信息。
- 长按用于减少误触，建议时长 2 秒。

### 6.3 求助补充信息页

报警成功后进入补充信息页。

字段：

```text
求助类型：
  人员落水风险
  儿童走失
  身体不适
  纠纷求助
  违规下水
  其他

联系电话
现场描述
上传图片（最多3张）
提交补充信息
```

业务逻辑：

- 即使游客不补充信息，求助事件也已经创建。
- 补充信息提交后，更新已有 `risk_event`。
- 联系电话建议必填，但第一版可以允许跳过，避免演示阻断。

### 6.4 安全上报页

上报页处理非即时生命危险的安全隐患。

分类：

```text
违规下水
儿童无人看护
救生设施损坏
夜间滞留
人员聚集
噪音纠纷
环境卫生
其他
```

建议采用分步式表单：

```text
1. 选择问题类型
2. 选择位置
3. 上传照片
4. 补充描述
5. 选择是否匿名
6. 提交
```

大厂化优化：

- 不要一屏堆满输入框。
- 每一步只问一个核心问题。
- 提交后明确告诉用户“可在进度页查看处理状态”。

### 6.5 进度页

进度页用于证明“上报有回音、处置有闭环”。

筛选：

```text
全部 | 求助 | 隐患 | 失物
```

记录卡片：

```text
事件类型
湾区位置
当前状态
提交时间
查看详情
```

状态：

```text
已提交
已受理
已派单
工作人员已到达
已完成
已归档
```

详情页采用时间轴，类似快递物流：

```text
19:31 已提交
19:32 已派单
19:34 工作人员已到达
19:39 已完成处置
```

### 6.6 我的页面

第一版保持轻量。

内容：

```text
微信头像 / 昵称
联系电话
我的求助
我的上报
失物招领
安全须知
隐私说明
关于江滩智防
退出登录
```

必须加入“隐私说明”，因为系统涉及定位、图片、联系方式和求助记录。
