# 窗口 02｜AI 智能中枢与智能体编排

## 目标

建立统一、可审计、可回退的 AI 能力中心。模型、知识库、Agent、Skill、MCP 和语音/视觉能力由同一套运行态契约对外提供，五大业务系统只调用能力，不各自维护一套 AI 规则。

## 必用技能与工具

- `api-design`：设计 AI 运行态与结果契约。
- `context7-mcp` 或 `find-docs`：需要查模型 SDK、向量检索或 MCP 协议时只查官方文档。
- `test-driven-development`：先写 AI 结果和路由契约测试。
- `verification-before-completion`：完成前验证错误回退、人工确认和审计字段。
- 使用 MCP 连接器时，只允许登记白名单连接器和只读范围；连接器不能绕过平台权限。

## 固定能力分层

```text
国产模型服务
  ├─ 文本理解与生成
  ├─ 语音转写与结构化
  ├─ 视觉与动作识别
  └─ 知识库与类案检索
        ↓
Agent（按业务角色）
        ↓
Skill（按场景触发）
        ↓
MCP（受控连接数据和工具）
        ↓
业务系统人工确认与审计
```

第一期模型适配 DeepSeek、Qwen3 等内网服务。模型名称是配置项，业务接口只依赖统一能力名。

## 统一 AI 结果类型

在前端和后端使用同一字段语义：

```ts
type AIResultContract = {
  result: string;
  confidence: number;
  evidence?: string[];
  evidenceTime?: string;
  explanation?: string;
  humanReviewRequired: boolean;
  reviewStatus: 'pending' | 'confirmed' | 'rejected' | 'not_required';
  fallbackAction?: string;
  auditId: string;
};
```

字段要求：

- `confidence` 范围固定为 `0—100`，后端校验越界值。
- `evidence` 为空时必须提供 `evidenceTime` 或明确的“暂无依据”说明。
- 高风险场景 `humanReviewRequired` 必须为 `true`，初始 `reviewStatus` 必须为 `pending`。
- `auditId` 每次结果唯一，格式为可追踪字符串，不使用前端随机临时值代替。
- `fallbackAction` 指向人工处理或回退流程，不能写成“自动执行”。

## AI 中心接口

### `GET /api/ai-center/runtime`

返回：

```json
{
  "model": { "name": "国产大模型（内网部署）", "status": "可用", "providers": ["DeepSeek", "Qwen3"] },
  "capabilities": [
    { "name": "文本理解与生成", "scope": "警单、卷宗、制度、报告", "status": "可用" },
    { "name": "语音转写与结构化", "scope": "接警、问询、移动勤务", "status": "待接入" },
    { "name": "视觉与动作识别", "scope": "训练动作、目标复核", "status": "按权限启用" },
    { "name": "知识库与类案检索", "scope": "法条、判例、内部制度", "status": "待接入" }
  ],
  "agents": [],
  "skills": [],
  "mcpConnectors": []
}
```

### `POST /api/ai-center/review`

请求体：

```json
{ "auditId": "ai-20260904-0001", "decision": "confirmed", "operatorId": "police-001", "reason": "人工核验通过" }
```

`decision` 只允许 `confirmed` 或 `rejected`。接口必须记录操作人、时间、原始结果和人工意见；拒绝时保留 `fallbackAction`。

## Agent、Skill、MCP 编排规则

### Agent

固定提供角色：

- 接处警协同 Agent：摘要、问询提示、分类分级建议。
- 执法办案助手 Agent：法律条文、证据清单、文书检查。
- 勤务训练教官 Agent：模拟评分、动作识别、短板画像。
- 移动勤务伴随 Agent：身份核验提示、现场指引、结果回传。

### Skill

固定提供触发器：

- `警情结构化抽取`：接警语音进入。
- `证据规则校验`：案件提交前。
- `训练短板画像`：训练结束后。
- `移动现场指引`：民警签收现场任务后。

### MCP

MCP 连接器必须声明 `name`、`status`、`scope`、`lastSync`，并经过权限白名单。禁止在 MCP 层直接写入案件、派警或审批状态；写入必须经过业务 API 和人工确认。

## 执行步骤

1. 新增 `scripts/verify_ai_runtime_contract.py`，先断言模型、能力、Agent、Skill、MCP 和 AI 结果字段。
2. 实现 `ai_runtime.py` 的 `normalize_ai_result()`、`runtime_snapshot()` 和 `review_result()`，所有异常返回可审计的回退结果。
3. 新增 `/api/ai-center/runtime` 与 `/api/ai-center/review`，在 `main.py` 注册 `/api` 前缀。
4. 在 AI 中心页面展示运行态、连接器范围和结果责任链；高风险结果必须出现人工确认按钮和回退说明。
5. 对模型不可用、知识库超时、MCP 权限不足分别写测试，验证不会直接改变业务状态。

## 完成标准

- AI 运行态接口返回稳定结构。
- 任一 AI 结果都能通过 `auditId` 找到原始结果和人工决定。
- 高风险结果默认待人工确认，拒绝后进入回退流程。
- 页面明确展示模型、Agent、Skill、MCP 的状态和权限范围。
