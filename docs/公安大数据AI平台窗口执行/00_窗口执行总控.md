# 公安大数据与 AI 平台｜窗口执行总控

> 适用日期：2026-09-04  
> 使用方式：每个新窗口只读取本文件和自己负责的窗口文档；完成后把“变更文件、测试命令、结果、未决项”回传给主窗口。

## 1. 固定交付目标

交付一个独立的“公安大数据与 AI 平台”Web 端和后端框架。平台采用以下固定分层：

```text
统一门户与组织上下文
        ↓
平台总览 / 数据资源中心 / AI 智能中枢 / 平台治理与安全
        ↓
接处警｜执法办案｜社区警务｜勤务训练｜移动勤务
        ↓
统一数据对象｜统一事件链｜统一身份｜流程｜消息｜审计｜运维
```

产品名称、页面标题、导航和 API 返回的项目标识统一使用：`公安大数据与 AI 平台`。

平台与其他产品保持独立品牌、独立路由和独立首页，不共用其他产品的名称、Logo、首屏叙事或业务指标。

## 3. 统一工程约束

- 保留当前工作区中其他用户改动；禁止 `git reset --hard`、整目录删除和覆盖无关文件。
- 每个窗口先写或补充失败测试，再做最小实现，再运行窗口专属测试。
- 页面必须使用中文公安业务术语，产品标题不得改成其他项目名称。
- 高风险 AI 建议只进入人工确认队列，不直接改变执法、派警、审批或案件状态。
- 所有 AI 结果必须包含：结果、置信度、依据或数据时间、解释要点、人工确认入口、回退操作、审计编号。
- 接处警后端键名固定为 `alarm`，前端路由固定为 `command`；勤务训练后端键名固定为 `training`，前端路由固定为 `duty-plan`。前端不得被运行态数据覆盖路由键。
- 原生按钮、输入框和链接必须可键盘操作；焦点状态可见；状态变化使用 `aria-live` 或等效语义。
- AI 模型默认按国产内网部署设计，适配 DeepSeek、Qwen3 等模型服务；模型供应商可替换，业务接口不可随模型名称变化。

## 4. 统一数据对象

第一期必须支持以下主数据对象，并能在 `/api/platform/overview` 返回目录摘要：

| 数据域 | 对象 |
|---|---|
| 组织与警力 | 机构、民警、岗位、在岗状态 |
| 警情与指令 | 警情、指令、处置结果、风险信号 |
| 案件与证据 | 案件、证据、卷宗、法律文书 |
| 人员与车辆 | 人员、车辆、轨迹、身份核验记录 |
| 社区与地址 | 网格、地址、重点人地事物、走访任务 |
| 训练与健康 | 课程、训练记录、评分、健康指标 |
