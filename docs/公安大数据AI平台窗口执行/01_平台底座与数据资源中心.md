# 窗口 01｜平台底座与数据资源中心

## 目标

把后端平台接口从“单个业务总览”提升为可支撑五大业务系统的统一数据底座。窗口结束时，前端可以只依赖 `/api/platform/overview` 展示平台总览、数据目录、业务系统状态和统一事件链。

## 必用技能与工具

- `api-design`：冻结 REST 字段、兼容规则和错误语义。
- `test-driven-development`：先写接口契约测试，再实现。
- `verification-before-completion`：完成前逐条执行测试并读回结果。
- 使用终端读取代码和运行测试；如需查库或接口文档，优先使用已有 MCP/项目资源，不引入新的外部服务。

## 只读输入

- `docs/公安大数据平台冻结交付方案.md`
- `docs/公安大数据AI平台窗口执行/00_窗口执行总控.md`

- `server/app/main.py`

- `apps/dashboard/src/pages/DashboardApp.tsx`

## 允许修改的文件

- `server/app/api/routes/platform.py`
- `server/app/main.py`（仅在平台路由未注册时补注册）
- `server/app/services/` 下与平台快照直接相关的服务文件
- `scripts/verify_platform_overview_contract.py`（新增）

不得修改页面视觉、五大业务页面或小程序代码。

## 固定数据模型

### 主数据域

必须返回 6 个数据域：`org`、`alarm`、`case`、`person`、`community`、`training`。每个域至少含 `key`、`label`、`description`、`objects`、`status`。

### 业务系统键名

```python
BUSINESS_SYSTEM_KEYS = ["alarm", "case", "community", "training", "mobile"]
```

`alarm` 和 `training` 是后端稳定键。前端分别映射为 `/command` 和 `/duty-plan`，后端不能返回 `command` 或 `duty-plan` 替代稳定键。

### 事件链

至少返回以下节点，顺序不可改变：

```text
接警 → 分类分级 → 派警 → 移动签收 → 案件办理 → 社区闭环 → 训练复盘
```

每个节点含 `label`、`count`、`status`。未接入数据使用“待业务上报”，不能伪造为“已完成”。

## 执行步骤

### 1. 写失败契约测试

在 `scripts/verify_platform_overview_contract.py` 中加入以下测试逻辑：

```python
from app.api.routes.platform import _runtime_snapshot

snapshot = _runtime_snapshot()
assert snapshot["project"] == "公安大数据与 AI 平台"
assert [item["key"] for item in snapshot["businessSystems"]] == [
    "alarm", "case", "community", "training", "mobile"
]
assert snapshot["dataCatalog"]["domainCount"] == 6
assert [item["label"] for item in snapshot["eventChain"]] == [
    "接警", "分类分级", "派警", "移动签收", "案件办理", "社区闭环", "训练复盘"
]
```

运行：

```powershell
& 'D:\CICSIC\server\.venv-runtime\Scripts\python.exe' scripts/verify_platform_overview_contract.py
```

### 2. 完善平台快照

在 `platform.py` 内保持 `_runtime_snapshot() -> dict[str, Any]` 作为唯一快照入口，完成以下检查：

- `project`、`subtitle`、`updatedAt`、`organization` 完整。
- `stats` 至少含 `today_events`、`pending_orders`、`online_staff`、`completion_rate`、`open_cases`、`community_tasks`、`training_records`。
- `events` 只返回标准公安事件字段，不把其他产品名写入标题、区域或说明。
- `dataCatalog.objectCount` 等于所有 `objects` 长度之和。
- `businessSystems` 的 `status` 和 `metric` 可以来自实际服务；无数据时返回“待接入”和 `0`。
- AI 运行态和治理字段即使暂无真实数据也返回稳定结构，避免前端空指针。

### 3. 保持路由注册稳定

确认 `server/app/main.py` 注册：

```python
from app.api.routes.platform import router as platform_router

app.include_router(platform_router, prefix="/api")
```

接口最终地址必须为 `GET /api/platform/overview`，不新增同义地址。

### 4. 增加异常回退

当事件库、运行态服务或可选模型服务抛出异常时：

- 接口仍返回 HTTP 200 和完整字段结构。
- 数值字段回退到 `0` 或 `None`。
- 状态回退到“待同步”或“待接入”。
- 不吞掉项目标识和业务系统键名。

## 完成标准

- 契约测试通过。
- `GET /api/platform/overview` 返回五个稳定业务系统键。
- 数据目录显示 6 个域，统一事件链显示 7 个节点。
- 不修改任何前端页面和小程序文件。
