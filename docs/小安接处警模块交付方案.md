## 2. 交付结论

本次接处警交付采用“一条真实事件链 + 一套脱敏演示控制”的实现方式：

```text
接警输入
  ↓
B1 接警工单：转写、结构化、风险提示、关联警情
  ↓ 人工确认摘要
B2 导航派警：路线推荐、警力选择、人工下达派警
  ↓ 事件库写入并推送移动端
移动勤务：签收、到场、开始处置
  ↓
B3 盘查核验：脱敏核验线索、关联记录、人工确认或回退
  ↓
B4 物证同步：附件上传、补充说明、证据索引
  ↓ 人工确认
研判移交：生成移交记录，保留接处警事件原状态和完整审计链
```

交付的核心不是四张静态页面，而是让以下对象能用同一个事件编号关联：

```text
接警事件 → 派警指令 → 移动任务 → 现场回传 → 物证索引 → 研判移交
```

联调模式使用隔离的脱敏事件，通过后端执行并保存业务动作；回放模式只重现冻结场景，不调用写接口。两种模式使用同一套页面组件和数据结构，但显示阶段与业务状态分别管理。演示控制只负责呈现时序，不能绕过人工确认、权限校验或后端落库。

| 接警文本登记 | 接收已有 `transcript`，按关键词分类并创建事件；不是音频转写服务，且 `autoAssign` 默认开启 | `server/app/services/security_ops.py` 中的 `record_voice_intake()` |
| 档案匹配 | 姓名、编号、标签和图像内容摘要匹配；分值是规则分，不是真实人脸识别概率 | `security_ops.compare_identity_archive()`、`/api/security-ai/face-match` |

### 3.2 当前缺口

1. `/command` 中部分 AI 操作只改变 React 本地状态，没有稳定写回当前事件。
2. B1、B2、B3、B4 尚未形成统一的页面阶段和后端内部状态。
3. Web `/mobile` 中的演示任务不等于已经接通的小程序巡防任务。优先复用真实小程序链路，不为接处警重造移动任务系统。
4. 物证上传接口已有，但缺少“来源阶段、发现人、发现时间、移交状态”等接处警语义。
5. 现有公共事件状态只有 `已提交`、`已派单`、`已接收`、`已到达`、`处理中`、`已完成`，不能直接把 B1-B4 全部塞进公共状态。
6. 当前项目已有脱敏演示和真实数据边界，但接处警页面需要把边界直接呈现出来，不能只写在说明文档中。
7. 现有 `recommend_route()` 会更新负责人和派单元数据，不能直接作为无副作用的“预览路线”调用。
8. 现有 `update_event()` 主要检查目标状态是否在枚举中，没有强制前后状态顺序；页面禁用按钮不足以防止跳步。
9. 现有事件写接口未体现接处警所需的完整身份、角色和事件归属校验。新模块不能仅在新路由加校验，却允许旧 `/assign`、`/status`、`/supplement` 绕过。
10. `/api/ai-center/review` 审核 AI 中心已有结果，不自动关联 B3 核验记录，不能用随意构造的审计号调用。

本节是 2026-09-06 的静态代码核对结果，不是性能、安全或端到端验收结论。后续开工先重新查看相关文件和 `git status`，保留用户已有修改。

### 3.3 复用原则

- 保留现有事件状态枚举，避免破坏群众端进度展示。
- 把接处警内部阶段放进事件内部上下文和审计时间线。
- 后端业务规则放进独立的接处警工作流模块，页面只调用小接口。
- 真实模式和演示模式共用字段、状态和错误处理；演示模式只替换数据源和呈现时序。
- AI 结果必须带依据、数据时间、生成方式、人工确认入口、回退动作和审计编号。有经验证的置信度才显示数值；规则分写“规则匹配分”，没有可靠数值则显示“不提供”，不能填写固定百分比。

## 4. 本期范围

### 4.1 本期必须交付

#### B1 接警工单页

- 接警事件进入指挥端队列。
- 报警转写文本和人工修订入口。
- 结构化字段：警情类别、报警位置、报警人、危险因素、联系方式和定位来源。
- 脱敏演示场景固定两条关联警情；实际业务按查询结果显示零条或多条，不强制凑出两条。
- 风险提示和关联依据。
- “确认警情摘要”人工动作。
- 摘要确认后的审计记录。

#### B2 导航派警页

- 当前警情的定位和路线预览。
- 135 快反组或实际责任警组的推荐。
- 车辆段、步行段、预计时间和距离分开展示。
- “确认分级派警建议”和“下达派警”分开。
- 派警成功后写入事件、通知移动端并显示派警审计。

#### 移动勤务衔接

- 移动端显示与 B2 相同的事件编号。
- 支持 `已接收 → 已到达 → 处理中 → 已完成` 的现有状态链。
- 现场结果回传到同一事件。
- 结果回传时支持文字和证据附件。

#### B3 盘查核验页

- 脱敏核验对象卡片。
- 核验进度、结果、依据和数据时间。
- 关联警情交叉记录提示。
- 人工确认核验线索或回退人工处理。
- 核验结果不直接改变派警、案件或人员定性。

#### B4 物证同步页

- 普通物品和异常物证按口述顺序出现。
- 票据、笔记本和备用手机标签的可辨识教学图片；占位图仅供开发，验收前必须替换为与剧情一致的素材。
- 证据上传、预览、删除待上传项和补充说明。
- 证据索引与当前事件绑定。
- “提交研判移交”动作和移交审计。

#### 演示控制

- B1-B4 阶段切换。
- 阶段内卡片逐项出现。
- 暂停、继续、重播、复位和跳转。
- 页面断线时显示离线快照；需要播放教学备用页时必须显式切换，不能把业务快照静默替换成剧情样例。
- 演示控制不自动调用派警、核验确认或移交确认接口。

### 4.2 本期明确不做

- 不接入真实公安身份库、真实案件库或真实人脸原始素材。
- 不把“涉恶”“团伙”“盗窃罪”等法律或案件结论交给 AI 自动判定。
- 不实现完整的第三幕串并案研判、GIS 推演和第四幕抓捕战术系统。
- 不实现真实 110 电话交换、运营商定位或生产级地图导航服务。
- 不改变群众端现有事件状态语义。
- 不把演示控制台当成生产业务操作台。

第三幕和第四幕只保留可供后续跳转的事件链入口。本期 B4 只负责把材料和线索移交给研判环节。

## 5. 统一状态与责任链

### 5.1 公共事件状态

公共事件状态继续使用现有枚举：

```text
已提交 → 已派单 → 已接收 → 已到达 → 处理中 → 已完成
```

状态含义：

| 状态 | 允许由谁产生 | 业务含义 |
|---|---|---|
| `已提交` | 群众端、接警端 | 事件已进入平台，尚未形成派警回执 |
| `已派单` | 指挥席人工确认后 | 已向指定工作人员下达任务 |
| `已接收` | 移动端工作人员 | 工作人员确认接收任务 |
| `已到达` | 移动端工作人员 | 工作人员确认到达现场 |
| `处理中` | 移动端工作人员 | 已开始现场处置 |
| `已完成` | 移动端工作人员或授权后台 | 现场处置结果已回传；不代表后续案件调查结束 |

### 5.2 接处警内部阶段

内部阶段写入 `event.meta.command.stage`，不替换公共状态：

```text
B1_INTAKE
B1_SUMMARY_PENDING_REVIEW
B1_SUMMARY_CONFIRMED
B2_ROUTE_READY
B2_DISPATCH_PENDING_REVIEW
B2_DISPATCH_CONFIRMED
B2_DISPATCHED
B3_VERIFICATION_PENDING
B3_VERIFICATION_CONFIRMED
B3_VERIFICATION_FALLBACK
B4_EVIDENCE_COLLECTING
B4_HANDOVER_PENDING
B4_HANDOVER_SUBMITTED
B4_HANDOVER_ACCEPTED
```

这是后端业务进度，不是当前打开的页面。读取上下文和切换 B1-B4 均不修改它，公共状态也不能在读取时自动推导成一个新的落库阶段。

| 动作 | 前置条件 | 成功结果 |
|---|---|---|
| 保存接警草稿 | 新接警或尚未派警 | 保存版本；实质修改使摘要和派警建议确认失效 |
| 确认摘要 | 地点文字、类别和待核实危险因素已记录；“不详”可作为明确值 | `B1_SUMMARY_CONFIRMED`，公共状态仍为 `已提交` |
| 预览路线 | 摘要已确认，指定候选警力；坐标可以缺失 | 返回只读方案；缺坐标返回空路线和手动地点说明，不修改负责人 |
| 确认派警建议 | 当前摘要版本与候选警力未改变 | `B2_DISPATCH_CONFIRMED`；保存方案摘要及确认记录，不下发任务 |
| 下达派警 | 当前建议已确认，操作者获授权，公共状态为 `已提交` | 同一事务写入 `B2_DISPATCHED`、公共状态 `已派单`、负责人和审计 |
| 接收、到场、开始处置 | 已派给当前人员，符合公共状态相邻转换 | 依次更新公共状态；内部阶段可暂留 B2，不强制退回 `已派单` |
| 查询或人工处理核验 | 当前任务已到场或处理中；操作者对该事件获授权 | 保存核验记录；确认结果、无匹配、转人工分别保存，不能直接跳到已确认 |
| 登记现场材料 | 已到场或处理中 | 保存材料索引；允许核验仍在等待时开始登记，不强迫为进入 B4 捏造核验结果 |
| 提交研判移交 | 至少一件本事件有效材料，核验已确认、已记录无匹配或说明转人工原因，移交摘要非空 | `B4_HANDOVER_SUBMITTED`，公共状态不变 |
| 接收或退回移交 | 移交已提交，接收角色有权操作 | 接收进入 `B4_HANDOVER_ACCEPTED`；退回保存原因并回到 `B4_HANDOVER_PENDING` |
| 完成现场任务 | 公共状态为 `处理中`，结果非空，本场景移交已获接收 | 公共状态 `已完成`；表示现场任务结束，不是案件侦查终结 |

材料补充与 B3 核验是可并行记录。已进入 B4 时，补记 B3 结果仅更新核验对象和审计，不把整体阶段倒退为 B3。移交提交冻结当次材料版本，退回后通过新版本补正；已接收的移交和已完成事件保持只读，本期不实现撤销归档。

同一动作重试不能产生第二张工单或第二条移交。请求提交后超时，客户端先读取回执核对，再用同一请求编号重试。紧急情况下的业务派警例外另由业务方确定；本期方案不得阻止现有人工接警或外部电话处置流程。

### 5.3 角色

| 角色 | 允许操作 |
|---|---|
| 接警员 | 查看接警输入、修订转写、确认摘要、发起问询 |
| 指挥席 | 查看风险提示、确认分级派警、下达派警、查看路线 |
| 处警人员 | 接收任务、到达、处置、现场核验、回传结果和材料 |
| 研判人员 | 接收 B4 移交、查看证据索引、反馈移交状态 |
| 教学演示员 | 控制页面阶段、播放节奏和静态备用页；不能替代业务确认 |
| 系统管理员 | 查看运行状态、审计和配置；不能绕过业务责任链修改执法结论 |

上述为本期目标权限，不能据此宣称现有接口已完成鉴权。新写接口从有效 Bearer token 解析操作者，客户端不得提交可信的 `operator`、`confirmedBy` 或审计编号。派警需指挥角色及 `dispatch` 权限，现场操作需绑定当前任务的人员及相应权限，移交接收需指定研判人员及 `analyze` 权限；演示控屏账号无业务写权限。测试账号在隔离环境显式配置，不依赖用户名或 openid 前缀猜测角色。

事件读取、附件访问和 WebSocket 消息也必须按角色与事件归属过滤；群众进度回执不能泄露 `meta.command`、核验资料或内部材料。涉及该事件的旧写入口统一调用同一授权和状态校验，避免新页面受控而旧接口仍能绕过。

### 6.2 数据边界

- `desensitized_demo` 只能使用脱敏姓名、脱敏照片、虚构编号和教学素材。
- `offline_snapshot` 属于前端连接状态，不写回 `sourceMode`，只读且不能触发写入性接口。
- `live` 仅表示非教学样例的事件数据，不表示已经接通公安生产系统；本期验收仍全部使用隔离教学样例。
- 所有模式均显示数据时间和来源。场景数据与真实事件通过环境和服务端配置隔离，不能仅靠前端筛选隐藏教学记录。
- 位置缺少有效坐标时，只显示手工地点，不生成虚假路线、距离或到达时间。
- 核验结果必须显示“线索”或“待人工确认”，不能显示为最终身份结论。

### 6.3 证据索引

现有 `meta.evidence` 和 `meta.context.evidence` 继续保存文件引用；接处警工作流额外维护 `command.evidenceIndex`，避免把图片 URL 当成完整业务记录。证据索引至少包含：

```text
证据编号、名称、类型、来源阶段、发现时间、发现人、文件地址、描述、敏感级别
```

上传失败、重复上传和事件不存在时，页面必须保留本地待上传状态并显示具体错误；不得显示“已入卷”。

登记材料时服务端校验上传回执、当前事件归属和访问权限，再生成 `evidenceId`、登记人和登记时间。图片/视频必须有可访问的文件引用；文字记录必须有非空内容。发现人可以登记为具体现场人员，但需属于该任务参与人员；登记人始终取登录身份，不由前端自报。首次范围仅支持图片、视频和文字，不把任意扩展名上传等同于文档处理能力。

三个索引的更新须在同一事务内提交，保留其他 `meta` 字段，并重新赋值 JSON 以触发持久化。移交只允许引用本事件已登记且文件仍可用的 `evidenceId`；不存在或属于另一事件的编号返回校验错误。文件上传但未登记成功的项目保留待登记回执，不重复上传，不显示已同步。

### 6.4 一致性与回执

写接口携带 `requestId` 和 `expectedVersion`。服务端以事件为范围校验版本，在事务内锁定当前记录后写业务状态、递增版本并追加审计。相同请求编号和相同内容返回原回执，内容不同则返回 `409`；幂等依据必须落库，不能只保存在进程字典。

派单必须把公共状态、内部状态和审计原子写入。需要复用 `event_store.assign_event()` 时，先提取可共享事务的内部动作，不能在两个自行提交的函数之间拼接“先派单、再保存确认”。事务成功后通知；通知失败保留派单记录并显示待同步，客户端重新查询可恢复，不能伪称已送达。

## 7. 页面与接口实现要求

### 7.1 B1 接警工单

**页面目标：** 让值守人员在一个屏幕内确认“谁、在哪里、发生什么、有没有升级风险”。

| 区域 | 内容 | 数据来源 |
|---|---|---|
| 来电弹屏 | 报警人、通话计时、来源渠道 | 语音接警记录或脱敏样例 |
| 转写区 | 报警原话、片段时间、输入方式、人工修订 | 本期人工文本或预录教学音频与对齐字幕；现有 `voice-intakes` 只接收文本 |
| 要素卡 | 位置、类型、危险因素、定位来源 | 事件对象和 `command.intake` |
| 关联卡 | 演示两条历史同类警情、时间、地点、手法标签、关联依据 | 本期新增的关联查询；真实结果不固定条数 |
| 操作区 | 确认摘要、修改位置、转人工 | 接处警工作流接口 |

默认展示文案：

```text
消费纠纷
存在升级风险，建议优先核实是否有人受伤、是否有危险物品及现场是否仍在冲突
关联警情：2 起
关联结果仅供人工核查
```

“涉恶升级预警”是附件中的演示标签。除非业务负责人确认该标签可以用于项目演示，否则产品默认使用“消费纠纷升级风险”，不提前作法律或案件定性。

接警创建只发生一次。经鉴权的接处警入口复用现有文本登记逻辑，显式传 `autoAssign: false`，并补充事务和幂等保护；创建和草稿修订同时形成可编辑的规则摘要及 `summary.version`，供后续确认引用。其后修订文本调用当前事件的草稿保存接口，不再次调用会创建事件的旧入口。真实 ASR 本期不作验收承诺：演示使用预录语音与字幕片段，缺录音时使用人工输入，禁止把逐字动画标为实时识别成功。

关联查询先按近7日、同一夜市或同类夜市场景、纠纷类型和已记录的“食品索赔”“威胁砸摊”特征检索。展示命中的字段和来源警情编号，按时间排序；结果来自授权事件集合。教学场景的基准时间写入版本化数据文件，不能因系统日期变化使“两起关联”消失。没有结果显示“未检索到”，查询失败显示“暂不可用”，二者不得混用。

### 7.2 B2 导航派警

**页面目标：** 让指挥席看懂派谁、为什么派他、怎么到达。

现有接口与本期处理：

```text
GET /api/events/{event_id}/route
    现有接口有修改负责人副作用，不用于 B2 只读预览。
PATCH /api/events/{event_id}/assign
    复用其内部派单能力；command 事件必须经过统一权限、建议确认和幂等校验。
GET /api/events/staff-tasks
    复用任务查询，并补齐服务端人员归属校验。
```

页面必须把两段路线分开：

```text
警力当前位置 → 夜市入口：骑行/驾车段
夜市入口 → B 区 7 号：步行段
```

当前后端的路线提供方为 `local_recommendation`，页面标为“本地估算示意，非道路导航”。B2 新增只读路线预览；教学场景使用经确认的夜市底图、入口和分段路线，标为“教学预设路线”。实际事件没有路网或入口坐标时只显示可核实的位置和估算说明，不凭坐标臆造可通行的道路。缺少目标坐标则不显示路线或 ETA，但可由指挥席说明手动地点后派警，不把地图服务作为派警的强制依赖。

教学页面显示“骑行至入口约3分钟”和“入口至现场步行200米”；步行耗时未确定时不展示总 ETA。地图图标的预设移动标为模拟演示，不能写成实时警力定位。

派警按钮分为：

1. `确认分级派警建议`：保存指挥席确认记录，不改变公共状态。
2. `下达派警`：调用第8节的受控派警接口，复用已有派单内部动作，成功后公共状态变为 `已派单`，再通知移动端。

更换警力、修改地点或摘要版本后，原派警建议确认失效。旧派单入口即使被直接调用，也必须执行相同的业务守卫。首次范围不含重派已签收任务；遇到重派需求进入变更记录，不能直接重置状态。

### 7.3 B3 盘查核验

**页面目标：** 展示核验线索和人工责任，不把算法相似度包装成身份确定。

可复用的查询能力：

```text
POST /api/security-ai/face-match
```

此接口目前是本地档案规则匹配，不是人脸模型识别。优先按教学档案编号或姓名查询；返回的 `score` 标为规则匹配分。B3 由新工作流生成自己的 `verificationId` 和审计记录，再通过核验复核接口确认、登记无匹配或转人工。

没有登录或核验权限时仅能观看脱敏回放，不允许本地“确认成功”冒充服务器审核。教学页显示：

```text
教学训练仿真数据
核验结果为线索，需人工确认
数据来源：教学案例快照
回放中的步骤状态不代表本次业务操作已提交
```

在线联调则显示后端生成的记录时间和审计号。`/api/ai-center/review` 本期不作为 B3 复核入口，只参考其 token 解析和审核责任模式；没有明确记录映射时不得复用它的审核结果。

“与两起警情存在交叉”来自本场景已登记的人员引用，单独列出依据，不能由姓名相似或图像文件摘要相同推导。无匹配或服务失败允许人工记录并说明原因，不要求为了进入 B4 强行点“核验通过”。服务失败时仍保存查询尝试和 `verificationId`，该记录只可转人工，不能直接确认为匹配成功。

### 7.4 B4 物证同步

**页面目标：** 让观众和业务人员看懂“现场发现了什么，以及这些材料如何进入研判”。

复用接口：

```text
POST  /api/events/evidence
PATCH /api/events/{event_id}/supplement
GET   /api/events/{event_id}
```

界面顺序：

1. 普通物品清单逐项出现。
2. 交易小票缩略图阵列出现。
3. 笔记本中的交易记录关键字放大。
4. 备用手机标签出现。
5. 操作人员补充说明。
6. 证据索引确认。
7. 提交研判移交，在本工作台的接收侧完成接收或退回。

本期默认使用 8 张交易小票素材，以满足 9.5 需求书的明确呈现要求。若脚本后续改回“七八张”，只改演示数据快照和台词映射，不改证据对象结构。

研判移交提交后：

- `command.handover.status = submitted`
- 事件时间线新增“提交研判移交”
- 事件公共状态保持当前值
- 研判中心接收后才变为 `accepted`
- 被驳回时保留原证据和驳回原因，回到 `B4_HANDOVER_PENDING`

## 8. 后端实现拆分

### 8.1 新增工作流模块

计划新增：

```text
server/app/services/command_workflow.py
```

模块职责：

- 通过明确写操作初始化或更新 `CommandContext`；查询保持只读。
- 校验 B1-B4 内部阶段转换。
- 保存摘要确认、核验结果和移交记录。
- 统一生成接处警操作审计。
- 从事件对象中读取和合并证据索引。
- 提供经隔离的脱敏场景初始化与冻结快照；重复初始化返回同一轮事件，不覆盖已有记录。

模块按下面的路由职责封装校验、事务与审计。对外接口不接收任意 `meta` 覆盖，也不允许客户端直接设置 `stage`。内部复用事件服务时，应明确传递事务和已校验的操作者对象，不从客户端字符串构造身份。

场景文件计划为 `server/app/data/command/night_market_b1_b4_v1.json`，包含 `scenarioId`、`version`、`baseTime`、报警文本与字幕、两起关联纠纷、教学人员引用、分段路线、物品及素材清单。文案数字只在此处维护，由接口供展示与备用截图使用，不在四个页面分别硬编码。

### 8.2 新增路由模块

计划新增：

```text
server/app/api/routes/command.py
```

以下为接口基线，现已在 `command.py` 中实现；实际验证范围见实现交付记录。表内事件接口统一前缀为 `/api/command/events/{event_id}`。补充接口为 `POST /status` 和 `GET /receipts/{request_id}`，分别服务移动任务状态与超时回执核对。

| 方法与路径 | 业务字段，不含公共请求字段 | 作用与约束 |
|---|---|---|
| `POST /api/command/intakes` | `transcript`、`bay`、可选合法坐标和联系方式 | 一次创建事件和接警记录，禁止自动派单 |
| `POST /api/command/demo-runs` | `scenarioId`、`scenarioVersion`、`runKey` | 仅教学隔离环境可用；初始化一轮样例，不改变其他轮次 |
| `GET /context` | 无 | 读取事件、上下文和审计，未初始化返回 `command: null` |
| `PATCH /intake` | `transcript`、`locationText`、可选坐标 | 初始化或保存当前事件草稿；派警前修改使旧确认失效 |
| `GET /related-alerts` | 无 | 返回授权范围内的关联结果与依据，不写业务状态 |
| `POST /summary/confirm` | `summaryVersion`、`category`、`text`、`riskTags`、`dangerFactors`、`note` | 人工确认摘要，留存依据 |
| `GET /route-preview` | 查询参数 `staffId` | 只读返回候选路线和依赖版本；不得修改负责人和任务状态 |
| `POST /dispatch/confirm` | `staffId`、`summaryVersion`、`locationVersion`、`note` | 服务端校验并冻结当前派警建议，生成 `recommendationId` |
| `POST /dispatch` | `recommendationId` | 原子写入派单、内部状态和审计；旧入口守卫一致 |
| `POST /verification` | `query` | 服务端检索生成核验记录；不能提交预制的已确认结果 |
| `POST /verification/{verification_id}/review` | `decision` 为 `confirmed/no_match/fallback`、`reason` | 核验记录必须属于当前事件；转人工必须说明原因 |
| `POST /evidence` | `uploadId` 或文字记录、`name`、`discoveredAt`、可选 `discoveredBy`、`description` | 校验上传回执与发现人后登记材料，服务端生成证据编号 |
| `POST /handover` | `summary`、`evidenceIds` | 校验本事件证据并冻结当次移交版本 |
| `POST /handover/{handover_id}/review` | `decision` 为 `accepted/rejected`、`reason` | 接收或退回，审计与公开事件状态分离 |

公共写字段为 `requestId` 和 `expectedVersion`；新建事件或新轮次无事件版本，只要求请求编号。历史事件首次通过 `PATCH /intake` 初始化时使用 `expectedVersion: 0`，初始化后从1递增；数据模式由服务端环境和场景记录决定。返回统一为 `{ event, command, auditId, requestId }`；查询集合使用 `{ items }`。

上传回执沿用 `/api/events/evidence`，为 command 材料增加必填的事件归属，返回 `uploadId`、`url`、`mimeType`、`size`、`sha256`，并由服务端记录上传者。旧客户端的非 command 上传行为通过回归测试保持兼容。不能以任意 URL 替代服务端回执，只有已授权人员能获取所引用文件。

未登录返回 `401`，权限不足 `403`，事件或子记录不可访问/不存在 `404`，阶段、版本或重复请求内容冲突 `409`，字段或证据归属不合法 `422`。错误响应保留请求编号，客户端显示原因并保留草稿。成功响应必须可通过后续 GET 再次读取。

## 10. 演示控制与联排

### 10.1 控制状态

控制器至少维护：

```ts
type DemoStage = 'b1' | 'b2' | 'b3' | 'b4' | 'handover' | 'fallback';

type DemoControlState = {
  stage: DemoStage;
  paused: boolean;
  currentReveal: number;
  mode: 'rehearsal' | 'playback';
  connectionState: 'online' | 'offline_snapshot';
  runKey: string;
  eventId: string | null;
  scenarioVersion: string;
  lastError?: string;
};
```

`rehearsal` 是隔离环境中的在线业务联调，`playback` 是只读教学回放。回放复位只重置画面；重新做一次业务联调必须显式创建新 `runKey`。旧回执、审计和证据仍保留。页内空格键暂停的是呈现计时，不伪造真实警情的业务时间。

控屏与大屏使用同一 `/command` 入口的不同展示参数，例如 `?surface=control` 与 `?surface=display`，并携带相同 `runKey`。默认同机双窗口；展示窗口隐藏工作台导航与按钮。页面参数不能提升权限。首期可用同源窗口通信同步视觉步骤并在重连时重新获取快照；跨机器控屏需要受鉴权的后端会话支持，未实现前不得承诺。

### 10.4 联排顺序

1. 使用同一条脱敏事件进入 `/command`。
2. B1 播放来电、转写和关联警情；确认摘要。
3. B2 预览两段路线；确认建议并下达派警。
4. 在小程序巡防端确认同一事件已进入任务列表；Web `/mobile` 未完成绑定前不能作为替代验收证据。
5. 移动端完成接收、到达、处理中；保存现场记录草稿，暂不点击完成。
6. B3 展示脱敏核验线索；执行确认或回退。
7. B4 逐项呈现证据；上传或读取冻结素材。
8. 提交研判移交，研判接收侧确认；移动端再提交现场结果并完成任务，核对各自回执。
9. 刷新页面确认数据可恢复；断开接口查看离线提示，显式切换教学备用页，不显示虚假在线状态。
10. 复位演示控制并回放一次；确认不删除业务记录、不重复派警、不重复提交材料。

## 11. 异常和降级

| 情况 | 页面行为 | 业务状态 |
|---|---|---|
| 音频或字幕不可用 | 保留原始输入，提示人工录入；不宣称已完成 ASR | 仍为 `B1_INTAKE` |

| 派警接口失败 | 保留页面输入，显示重试 | 仍为未派警状态 |
| 核验服务不可用 | 转人工核查，保留查询内容 | `B3_VERIFICATION_FALLBACK` |
| 文件上传失败 | 保留本地待上传项，显示失败原因 | 不进入正式证据索引 |

| WebSocket 断开 | 显示断线和最后同步时间，支持手动刷新 | 不伪造实时状态 |
| 页面刷新 | 重新读取事件上下文和时间线 | 状态从后端恢复 |
| 请求结果未知 | 显示“正在核对回执”，GET 确认后按原请求编号重试 | 不直接显示失败或第二次发单 |
| 切换事件后旧响应到达 | 丢弃与当前事件/请求版本不符的响应 | 不污染当前事件 |
| 研判退回 | 显示原因与原提交版本，允许补正后重新提交 | `B4_HANDOVER_PENDING`，保留历史记录 |

## 15. 已确定的口径和变更规则

### 15.1 本方案直接确定

1. 以现有 `/command` 路由为入口，不新增平行接处警首页。
2. 以现有 `event_store` 事件对象为主数据，不另建第二套事件库。
3. 公共事件状态不扩展，接处警进度放入 `meta.command.stage`，展示页码单独管理。
4. B2 的派警必须人工确认，AI 只提供建议。
5. B3 只生成核验线索，不生成身份或案件结论。
6. B4 提交研判移交不等于事件办结。
7. 无有效坐标时不生成虚构路线、距离和 ETA。
8. 本期使用八张脱敏交易小票素材。

## 17. 完成定义

只有同时满足以下条件，才可以宣布本模块交付：

1. 一条脱敏事件能够从 B1 走到 B4，并保留同一事件编号。
2. B2 派警后移动端确实能收到同一事件任务。
3. B3 和 B4 的确认、回退、上传和移交均有后端记录。
4. 刷新页面后状态、证据和审计记录可恢复。
5. 接口不可用时页面能明确降级，不伪造在线成功。
6. 自动验证命令和 Dashboard/小程序构建均通过。
7. 16:9 演示视口下完成一次不依赖鼠标暴露的 B1-B4 联排。
8. 验收记录、静态备用素材和本方案版本号一致。

上述八项是正式交付的完成条件，不表示当前代码阶段交付已全部达到。下一轮优先补齐真实终端验收，不提前扩展第三幕、第四幕。
