## 1. 改版目标

本次改版目标是参考 Figma 中的新小程序页面，将当前 `apps/miniprogram` 的 Taro 小程序界面调整为更轻量、紧凑、清晰的移动端工作流界面。

改版不改变第一版的核心业务闭环：游客登录、便民首页、紧急求助、问题反馈、进度追踪、工作人员接单处置、详情查看。重点是重构页面布局、视觉层级、卡片样式、状态表达和操作按钮。

## 4. 设计语言提炼

### 4.1 视觉方向

新稿整体从当前“展示型、较大圆角、强背景层次”的风格，转向“工具型、轻卡片、细边框、紧凑信息密度”的风格。

主要特征：

- 页面宽度按 390px 移动端画板设计。
- 页面背景偏浅，内容以白色卡片承载。
- 卡片圆角主要为 8px 和 12px。
- 边框比阴影更重要，常见边框色为浅蓝灰。
- 状态色直接用于标签、按钮和左侧状态条。
- 文本字号更克制，标题常用 18px，正文常用 14px，辅助标签常用 12px。

### 4.2 建议色板

| 用途 | 色值 | 说明 |
|---|---|---|
| 主色 | `#006D77` | 主按钮、工作人员处理中操作 |
| 主色深色 | `#00535B` | 链接、描边按钮、重点数字 |
| 正文 | `#181C1D` | 标题和主要文本 |
| 次级文本 | `#3E494A` | 位置、时间、说明 |
| 边框 | `#BEC8CA` | 卡片外边框 |
| 分割线 | `#EBEEEF` | 卡片内部横线 |
| 高风险 | `#E29578` | 高风险标签、按钮、状态条 |
| 处理中高亮 | `#9FF0FB` | 处理中标签、状态条 |
| 完成/安全 | `#236863` | 已完成数字、成功状态 |
| 待接收红色 | `#BA1A1A` | 待接收数量 |

### 4.3 字体策略

Figma 中出现 `WenQuanYi Zen Hei`、`Public Sans`、`Plus Jakarta Sans`。小程序端不建议引入远程字体，实施时统一使用当前项目已有字体栈：

```scss
font-family: -apple-system, BlinkMacSystemFont, 'PingFang SC', 'Microsoft YaHei', sans-serif;
```

数字可通过 `font-weight` 和颜色突出，不单独引入英文字体。

## 5. 页面改造方案

### 5.1 工作人员任务页

建议作为第一批改造页面。

当前页面位置：`StaffWorkView` 中 `staffTab === 'tasks'` 分支。

保留：

- 工作人员顶部身份栏。
- `任务 / 地图 / 台账 / 我的` 顶部 tab。
- 现有 `events` 数据源。
- `advanceOrder` 状态推进逻辑。
- 工单详情跳转能力。

改造：

- 不再复用全局 `MetricCard`，新增工作人员任务页专用指标卡样式。
- 指标卡改为数值在上、标签在下。
- 增加“今日任务 / 全部 >”标题行。
- 任务卡改为 Figma 的结构：标签行、时间、标题、位置行、分割线、操作区、左侧状态条。
- 根据状态生成按钮：
  - 待接收或已派单：`接收任务` 或高风险时显示 `去处理`
  - 已接收或已到达：显示下一步推进按钮
  - 处理中：显示 `更新进度` 和 `完成巡检`
- 点击卡片或次级按钮进入详情，不在列表中默认展开大段详情。

### 5.2 游客首页

当前页面位置：`HomeView`。

保留：

- 地图组件。
- 紧急求助独立页。
- 服务入口。
- 最新服务进度。
- 两滩七湾点位数据。

改造：

- 顶部改为 Figma 的状态 Bento 区：天气、客流、水位。
- 地图区改为更标准的白底卡片容器。
- 状态指标从当前较厚重的卡片改为轻量 3 列卡片。
- 紧急求助保留独立页，首页改为便民服务入口。
- 服务入口改为 4 个轻量图标按钮。
- 最新活动改为窄条提示，不再占用大卡片空间。

注意：Figma 中地图像截图，项目里应继续使用 Taro `Map` 组件，不应替换成静态图片。

### 5.3 登录入口页

当前页面位置：`LoginEntry`。

保留：

- 游客入口。
- 工作人员入口。
- 语言选择能力。
- 项目 logo。

改造：

- 背景改为抽象江滩/河流图形感。
- 品牌区居中，减少当前大卡片厚重感。
- 增加信息信任卡片，承载“江滩智防服务”等提示。
- 两个入口按钮按 Figma 尺寸压缩为 44px 高度。

待确认：语言选择是否继续在登录页直接展开，还是收入口下方设置项。

### 5.4 游客我的页

当前页面位置：`MineView`。

改造：

- 头像身份卡改为 64px 头像 + 用户信息。
- 服务记录按列表项组织。
- 设置/说明项保持现有点击逻辑，只调整为细边框列表。
- 语言选择可以保留，但建议降级为普通列表项，减少页面占用。

### 5.5 服务详情页

当前页面位置：`src/pages/detail`。

改造：

- 顶部状态卡突出当前状态、湾区、时间和负责人。
- 时间轴改为纵向卡片式进度。
- 位置地图作为独立白色卡片。
- 详细信息采用 label/value 两列排布。
- 底部操作区做成固定底栏，保留“联系/导航/主要操作”。

注意：如果详情页同时承载游客详情和工作人员工单详情，需要通过 `type` 或 `mode` 做样式兼容，不建议拆成两个页面。

## 6. 组件与样式拆分建议

为避免影响游客端已有样式，第一批改造建议使用工作人员端局部 class，而不是直接改全局 `.metric-card`、`.order-card`。

建议新增或调整的 class：

| Class | 用途 |
|---|---|
| `.staff-task-dashboard` | 工作人员任务页内容容器 |
| `.staff-task-metrics` | 顶部指标卡网格 |
| `.staff-task-metric` | 单个指标卡 |
| `.staff-task-section-head` | 今日任务标题行 |
| `.staff-task-list` | 任务列表 |
| `.staff-task-card` | 新任务卡 |
| `.staff-task-card.high-risk` | 高风险卡片 |
| `.staff-task-card.processing` | 处理中卡片 |
| `.staff-task-card.pending` | 待接收卡片 |
| `.staff-task-tags` | 标签组 |
| `.staff-task-tag` | 标签 |
| `.staff-task-location` | 位置行 |
| `.staff-task-actions` | 操作按钮区 |

后续如果游客页也完成改造，可以再抽出更通用的 `status-card`、`mini-metric`、`section-title` 等组件。

## 7. 数据适配方案

当前任务数据来自 `useSafetyEvents()`，任务字段足够支撑 Figma 任务卡。

| Figma 字段 | 当前数据来源 |
|---|---|
| 任务标题 | `item.title` |
| 风险标签 | `item.level` |
| 状态标签 | `item.status` |
| 时间 | `item.updatedAt` |
| 位置 | `item.bay` + `item.distance` |
| 任务类型 | 可优先使用 `item.source`，不足时根据 `kind` 推断 |
| 操作按钮 | 根据 `item.status` 和 `nextAction(item)` 生成 |

如果需要完全还原 Figma 示例中的“常规巡检、设备维护”，可以在 mock 数据中补充 `category` 字段。但第一版不建议扩展数据结构，先通过现有字段映射。

## 8. 实施顺序

### 第一阶段：工作人员任务页

1. 修改 `StaffWorkView` 的任务 tab JSX。
2. 新增工作人员任务页局部样式。
3. 保持 `advanceOrder`、`openDetail` 和事件数据不变。
4. 构建微信小程序，确认 TypeScript 和 Taro 编译通过。

### 第二阶段：游客首页

1. 重排 `HomeView` 顶部状态区。
2. 保留真实 `Map`，只改外层容器和信息层。
3. 重做求助按钮、服务入口和最新活动提示。
4. 校验底部导航不遮挡内容。

### 第三阶段：登录页、我的页、详情页

1. 登录页对齐 Figma 背景和入口按钮。
2. 我的页调整身份卡和列表。
3. 详情页按状态卡、时间轴、地图、信息区、底部操作重排。

### 第四阶段：统一清理

1. 清理被替换的旧样式。
2. 抽取重复卡片样式。
3. 检查微信和支付宝构建输出。
4. 在真机或开发者工具中检查文字溢出、按钮高度和地图区域。

## 9. 风险与待确认事项

| 问题 | 建议 |
|---|---|
| Figma 图标是远程 SVG，链接会过期 | 小程序代码中优先用 CSS 简化图标；必要图标下载入 `src/assets` |
| Figma 字体不适合小程序直接引入 | 使用系统中文字体栈 |
| Figma 有些地图是静态图片 | 项目中继续保留 Taro `Map` |
| 全局卡片样式复用较多 | 第一阶段用局部 class，避免影响游客端 |
| 当前页面比 Figma 功能更多 | 以“不丢业务能力”为原则，视觉收敛但保留入口 |
| 工作人员任务页展开详情与 Figma 冲突 | 列表保持紧凑，详情通过点击进入或按需展开 |

## 10. 建议确认的问题

1. 是否先从工作人员任务页开始改造。
2. 登录页的语言选择是否继续直接展示。
3. 游客首页是否保留当前 5 个底部 tab，还是按 Figma 的 3 个 tab 调整。
4. 工作人员任务页是否保留顶部深色身份栏和四个 staff tab。
5. 详情页底部操作是否要固定在屏幕底部。

## 11. 推荐结论

建议采用渐进式改造：先对齐工作人员任务页，确认整体风格后再扩展到游客首页、登录页、我的页和详情页。

这样可以避免一次性改动过大，同时能尽快验证 Figma 新风格是否适配当前 Taro 小程序和既有业务流程。
