# 烟火哨兵项目计划书

版本：完整计划书初稿  
日期：2026年8月27日  
项目定位：夜市夜游与夜市商圈安全治理与训练平台  

## 一、执行摘要

烟火哨兵先做的是一套给夜市夜游、滨江文旅街区、夜市商圈和夜间活动场景用的安全治理平台。它把群众端小程序、巡防人员移动端、Web 指挥后台、后端事件库、分析能力和巡查能力串在一起，先把“能用、能看、能留痕”做出来，再慢慢往试点和复制上走。

项目当前已经有可运行的原型：群众或商户可以在小程序端发起求助、隐患上报和线索登记；后端能生成事件工单、报警推送和审计日志；巡防人员端能接收任务、同步位置、更新处置状态；Web 指挥后台能看运行总览、事件队列、点位地图、派单路线和处理结果。现在这套原型可以继续往夜市夜间安全治理试点、学校创新创业项目、警务实训成果转化和文旅街区安全运营工具几个方向推进。

本计划书建议项目先从轻量试点开始。第一阶段把夜市核心点位跑通，做出能演示的处理链路；第二阶段整理成可以交付的运营版产品和课程材料；第三阶段再往文旅街区、夜市商圈、活动安保和职业院校实训场景扩展，逐步形成平台订阅、试点建设、设备集成、运营报告和训练服务等收入。

## 二、项目背景

夜市空间既是城市公共休闲空间，也是夜间文旅消费、散步健身、节庆活动、摊位经营和亲水游览高度叠加的开放区域。晚间人流密度、摊点经营、车辆停放、酒精消费、短视频传播、临水空间和临时活动会让安全治理变得更复杂。夜市治理关注的不只是单个事件，而是一整条从苗头发现到现场处置、从证据固定到复盘训练的链条。

从实际场景看，夜市夜间安全治理通常会遇到以下高频问题：

- 人员聚集、推搡、酒后口角、纠纷升级等治安苗头。
- 扒窃、遗失物品、疑似尾随、儿童走失等群众求助。
- 临水区域、台阶坡道、骑行穿行、夜间照明和散场拥堵带来的安全隐患。
- 临时摊位、噪声扰民、经营纠纷和停车秩序问题。
- 节假日、演出、烟火秀、赛事活动等带来的人流峰值和多部门联勤需求。

传统做法主要靠固定监控、人工巡逻、电话报送和事后台账，基础秩序能管住，但早期线索怎么聚、不同角色怎么协同、现场进度怎么同步、处置结果怎么回看，这几件事往往还是散的。烟火哨兵想做的，就是把发现、派单、处置、留痕和复盘放到一条线上。

## 三、项目愿景与建设目标

项目愿景很直接：先做一套适合夜市开放空间的安全治理平台，让群众求助更顺手，让巡防处置更快一点，让指挥调度看得更清楚，后面的训练和运营也有东西可用。

总体目标：

- 建成“群众端 + 巡防端 + 指挥端 + 后端事件库”的基础产品体系。
- 建成夜市重点网格、联动点位、事件类型、人员任务和处置流程的标准化方案。
- 建成从求助上报、报警推送、指挥派单、人员接收、到场处理、结果回填到审计留痕的一条完整链路。
- 建成面向警务实训、安保培训和基层治理复盘的案例库与训练素材库。
- 形成可面向夜市夜游、夜市商圈、文旅街区和大型活动复制的商业化交付方案。

阶段目标：

| 阶段 | 时间 | 建设重点 | 阶段成果 |
|---|---:|---|---|
| 原型完善期 | 0-3个月 | 打通小程序、后端、指挥后台和巡防端处理链路 | 可演示样板、试点脚本、基础事件库 |
| 试点验证期 | 3-6个月 | 接入真实点位、真实人员账号、消息通知和运营报表 | 夜市试点报告、处置流程模板、培训材料 |
| 产品成型期 | 6-12个月 | 完成权限体系、设备接入、低空巡查协同和标准化部署 | 标准产品包、运维手册、报价体系 |
| 区域复制期 | 1-3年 | 拓展文旅街区、夜市商圈、安保企业和职业院校 | 多场景客户、课程包、专业增强版 |

## 四、痛点分析

### 4.1 风险识别：现场信息分散，苗头风险需要更早汇聚

夜市场景面积大、开放性强，夜间人流在不同入口、亲水平台、餐饮点、停车区和演艺活动区之间不断移动。固定摄像头能够覆盖重点点位，但难以完整覆盖临时摊位、背街通道、临水边缘和人群移动过程。巡防人员现场经验很重要，但单靠人工巡查容易出现信息滞后。

烟火哨兵把群众上报、商户平安码、巡防反馈、固定视频画面、无人机巡查和历史事件热力放在一起看，先把零散线索收拢起来。它不替代现场判断，只是帮指挥和巡防人员更快看到重点点位和可用线索。

### 4.2 响应调度：警情进入后，人员、路线和状态需要同步

在突发求助发生后，指挥端需要快速知道事件位置、风险等级、现场描述、可用人员、距离路线和任务状态。若仍依靠电话或群消息流转，容易出现“谁接单、到哪了、是否处置、是否需要支援”不清晰的情况。

项目将事件流转拆成“已提交、已派单、已接收、已到达、处理中、已完成”六段状态，并把人员定位、路线推荐、报警推送确认和处置结果回填接入同一事件库。这样指挥端能看运行情况，巡防端能看任务，群众端能看进度，后端能保留全过程台账。

### 4.3 协同复盘：多方参与后，需要形成可审计、可训练的记录

夜市安全治理往往涉及公安、城管、文旅运营方、安保企业、商户、志愿者、医疗救援点和设备服务方。事件处置结束后，如果缺少统一台账，后续很难沉淀“哪个点位高发、哪类事件常见、哪个时间段需要增援、哪条路线更快、哪种处置策略有效”。

每次处置都会留下结构化记录，包括来源、位置、风险等级、负责人、处置状态、路线信息、补充说明、结果回填和审计日志。做过脱敏后，这些记录能拿去做实训、培训、复盘和节假日预案调整。

## 五、解决方案

整体上，我们把它拆成平台、看板、模块和终端几块，方便后面按场景往下接。

一个平台：烟火哨兵一体化治理平台，负责接事件、看情况、派任务、做台账和整理复盘材料。

三张图：

- 热力图：展示夜市重点网格、事件密度、客流压力、风险等级和时段变化。
- 巡防部署图：展示在线巡防人员、联动点位、装备点位、推荐路线和任务状态。
- 事件轨迹图：展示单个事件从上报到完成的全流程轨迹和审计记录。

四个模块：

- 训：把真实处置流程转化为训练脚本、评分规则和案例库。
- 巡：用巡防端、地图点位、路线推荐和低空巡查辅助日常巡逻。
- 研：对多源线索进行分类、归并、风险标签和趋势分析。
- 处：完成求助上报、指挥派单、到场处置、证据固定和结果回填。

五个终端：

- 群众端小程序：面向游客、市民、商户，提供求助、上报、进度查询和安全提醒。
- 巡防人员端：面向一线巡防和安保人员，提供任务接收、路线查看、状态更新和结果回填。
- Web 指挥后台：面向指挥人员，提供运行总览、事件队列、点位地图、派单协同和处理记录。
- 后端管理端：面向系统管理和运维人员，提供接口健康、事件库、审计日志、人员设备和权限配置。
- 训练复盘端：面向学校、培训机构和管理部门，提供案例复盘、课程材料和演练评价。

## 六、产品功能设计

### 6.1 群众端小程序

群众端尽量做得轻一点。游客或商户打开小程序后，能看到重点点位、附近联动点、安全提醒和事件进度，也能直接发起求助或隐患上报。

主要功能是：

- 微信登录：通过微信小程序登录链路获取用户身份，后端换取 openid 和系统 token。
- 一键求助：同步所在点位、事件描述和联系方式，向指挥端生成高优先级事件。
- 隐患上报：支持街霸滋扰、打架斗殴、扒窃线索、摊位纠纷、噪音扰民、停车拥堵等类型。
- 线索登记：支持遗失物品、疑似扒窃、儿童走失等线索登记。
- 我的进度：查看已提交事件的状态、负责人、补充说明和处置结果。
- 安全提醒：展示重点时段、重点网格、天气客流、临水提醒和应急联系方式。

### 6.2 巡防人员移动端

巡防端主要给一线处置用，重点是任务别含糊、路线别绕、状态能及时更新。

主要功能是：

- 今日任务：展示待接收、处理中、已完成工单数量。
- 工单卡片：展示事件标题、位置、风险等级、来源、负责人、距离和状态。
- 状态流转：支持接收任务、确认到达、开始处理、完成处置。
- 地图视图：展示夜市网格、巡防点、事件点、本人位置和推荐路线。
- 处置回填：支持填写现场情况、处理结果和是否需要后续跟进。
- 台账视图：查看本人任务记录，形成可追溯工作台账。

### 6.3 Web 指挥后台

指挥后台给值守人员和管理人员用，主要看运行情况、派任务、做协同。

主要功能是：

- 运行总览：展示今日事件、待处置任务、在线巡防、平均响应时间、处理完成率和高风险事件数量。
- 事件队列：按风险等级、状态、来源和时间筛选事件。
- 地图调度：展示夜市点位、事件位置、巡防人员、路线推荐和联动资源。
- 指挥派单：将事件派发给在线人员，并同步至巡防端。
- 报警推送：对一键求助事件进行确认、分派和跟踪。
- 处理记录：查看事件时间线、处置结果和复盘摘要。

### 6.4 后端与数据服务

后端用的是 FastAPI + SQLAlchemy + PostgreSQL，保证小程序、巡防端和指挥端看的是同一套事件数据。

核心数据表包括：

- `safety_events`：求助、上报、线索登记和工单流转事件。
- `alarm_pushes`：一键报警推送到指挥中心的确认记录。
- `event_audit_logs`：事件创建、派单、接收、到达、处理、结果记录。
- `wechat_users`：微信 openid、session_key、系统 token 和登录时间。
- `patrol_staff`：巡防人员账号、角色、在线状态、定位和交通方式。

核心接口包括：

- `POST /api/auth/wechat-login`：微信登录。
- `GET /api/events/overview`：运行概览。
- `GET /api/events`：事件列表。
- `POST /api/events/help`：群众或商户求助。
- `POST /api/events/reports`：隐患上报。
- `POST /api/events/lost-claims`：线索登记。
- `PATCH /api/events/{event_id}/assign`：指挥派单。
- `PATCH /api/events/{event_id}/status`：状态更新。
- `PATCH /api/events/{event_id}/supplement`：补充说明。
- `WebSocket /api/events/realtime`：实时事件同步。

## 七、技术路线

技术上，我们坚持辅助分析，最后的判断交给人，部署尽量轻，留痕要完整。

### 7.1 总体架构

前端层由 Taro 小程序和 React Web 指挥后台组成。小程序负责群众触达和巡防人员移动处置，Web 后台负责指挥调度和情况展示。服务层由 FastAPI 提供 REST API 与 WebSocket 实时通道。数据层使用 PostgreSQL 存储事件、用户、报警推送、审计日志、人员定位和配置数据。扩展层以规则引擎、风险标签、路线推荐和后续可接入的视频识别能力组成。

### 7.2 辅助能力

这一部分主要负责辅助判断，不直接做处置决定。后面可以慢慢补这些能力：

- 风险分类：根据事件类型、描述、时间、点位和历史数据生成风险等级建议。
- 线索归并：将同一时间、同一区域、相似描述的多条上报合并为一个事件包。
- 路线推荐：结合人员位置、事件位置和交通方式推荐响应路线。
- 复盘摘要：从处置日志中生成复盘摘要、改进建议和训练案例。
- 视频提示：接入固定视频或无人机画面，对聚集、追逐、摔倒、越界、异常停留等场景进行提示。

### 7.3 低空巡查协同

在具备合规飞行条件和管理授权的前提下，项目可以接入无人机巡查，作为补充视角。它不单独占一个中心位置，更多是补盲、看客流、看临水区域、回传现场画面，顺带给演练留素材。

低空巡查能力建议按三个层级推进：

| 层级 | 建设内容 | 适用场景 |
|---|---|---|
| L1 演示联动 | 手动飞行、手动回传、人工标注事件 | 项目路演、校内实训、样板演示 |
| L2 试点协同 | 固定航线、任务触发、指挥端查看画面 | 节假日巡查、重点活动保障 |
| L3 画面增强 | 画面识别、风险标签、事件自动关联 | 区域复制、进阶版交付 |

### 7.4 数据安全与隐私保护

项目会涉及位置、联系方式、事件描述、处置日志和现场图像，所以权限和最小必要原则要先立住。

建设要求：

- 小程序前端不保存 AppSecret 等敏感配置。
- 联系方式、openid、定位和事件详情只用于求助、回访、处置和审计。
- 事件数据按角色授权查看，群众只看本人提交记录，巡防人员只看分派任务，指挥端按权限查看全局。
- 训练和展示数据应做脱敏处理，避免暴露个人身份、联系方式和敏感位置细节。
- 后端接口使用 HTTPS、CORS 白名单、访问令牌、日志审计和数据库备份。

## 八、业务场景

### 场景一：夜市夜游一键求助

游客在夜市亲水平台附近遇到纠纷或身体不适，通过小程序一键求助。系统同步位置、联系方式和事件描述，后端生成高风险事件并推送至指挥后台。指挥端查看附近在线巡防人员和推荐路线，将任务派发给最近人员。巡防人员端接收任务、查看路线、到达现场、处置并回填结果。群众端可查看进度，后台形成审计记录。

### 场景二：商户隐患上报

商户发现摊位附近有酒后争执、围观聚集或疑似扒窃人员，通过平安码提交上报，可选择匿名或留联系方式。系统根据事件类型和点位生成风险等级，指挥端将事件列入待核查队列。巡防人员到场核实后更新状态，处置结束后形成复盘记录。

### 场景三：节假日客流疏导

节假日夜市客流增加，指挥端通过热力图查看入口、停车区、亲水平台和餐饮区压力。系统根据历史事件和现场上报提示重点网格，值守人员动态调整巡防路线，并将临水提醒、停车疏导和应急点位信息推送到群众端。

### 场景四：职业院校实训

学校将真实脱敏案例转化为实训脚本，设置“上报、分析、派单、到场、处置、复盘”完整流程。学生在不同角色中使用系统完成演练，教师依据响应时间、处置流程、证据固定、沟通规范和复盘质量进行评分。

## 九、市场与用户分析

目标客户主要分为五类：

| 客户类型 | 核心需求 | 产品价值 |
|---|---|---|
| 夜市和文旅街区运营方 | 提升夜间安全运营能力，形成可汇报台账 | 事件记录、运营报告、点位热力和应急联动 |
| 夜市商圈和商业综合体 | 管理摊位、人流、停车和纠纷处置 | 商户上报、巡防派单、服务点联动 |
| 安保企业和活动承办方 | 提升项目制安保的数字化交付能力 | 巡防任务、人员轨迹、处置台账和客户报告 |
| 职业院校和实训基地 | 将实战场景转化为课程和比赛成果 | 案例库、演练脚本、评分规则和成果展示 |
| 基层治理和联勤单位 | 需要轻量工具辅助巡查宣防和多方协同 | 快速部署、低成本试点、跨角色协同 |

市场进入上，我们打算先做样板，再谈扩展。前期不急着铺大盘子，先把 1-3 个夜市或夜市场景跑出来，拿到能展示的数据记录、运营报告、视频材料和合作证明，再往同类场景复制。

## 十、竞品与差异化

烟火哨兵可与传统视频监控平台、智慧警务平台、安保巡更系统、单一无人机巡查服务和战训课程系统形成对比。

| 对比对象 | 典型优势 | 烟火哨兵切入点 |
|---|---|---|
| 视频监控与物联厂商 | 设备能力强，感知覆盖广 | 聚焦夜市和夜市微场景，把感知接入处置链路 |
| 大型智慧警务平台 | 平台能力全面，组织协同成熟 | 轻量试点、快速部署，适合项目制和教学转化 |
| 安保巡更系统 | 人员签到和巡逻记录清晰 | 增加群众上报、自动派单、事件状态和复盘训练 |
| 单一无人机服务 | 空中视角机动灵活 | 将低空巡查纳入事件、指挥、证据和训练链路 |
| 战训课程系统 | 适合教学和演练 | 以真实治理原型提供可操作、可复盘的训练素材 |

项目差异化不在于把所有功能都做得很重，而在于围绕夜市夜间安全治理把几个关键环节串起来：群众能报，指挥能派，人员能处，后台能看，数据能留下，试点能继续往外推。

## 十一、商业模式

项目建议先按试点建设、年度服务、设备集成、运营报告和训练课程这几项来算账，后面再看场景加减。

| 产品包 | 建议价格 | 交付内容 | 适用客户 |
|---|---:|---|---|
| 试点样板包 | 3-6万元/点 | 点位配置、原型部署、处理链路演示、试点报告 | 夜市样板、夜市试点、学校实训 |
| 运营服务版 | 8-18万元/年/点 | 小程序、指挥后台、事件库、运营报表、基础运维 | 文旅街区、夜市商圈、运营公司 |
| 进阶版 | 20-45万元/年/点 | 低空巡查接入、视频提示、权限体系、专项报表 | 大型活动、重点街区、安保企业 |
| 战训课程包 | 1-3万元/套 | 演练脚本、案例库、评分表、教学材料 | 职业院校、培训基地、安保培训 |
| 区域定制版 | 50-120万元/年 | 多点位平台、接口对接、专题看板、运营分析 | 区县平台、集团化商圈、文旅集团 |

商业路径建议还是先从容易落地的部分开始：

1. 以校内实训、夜市样板和夜市样板建立产品可信度。
2. 通过街区运营方、安保企业、文旅活动承办方获得项目制收入。
3. 将可复用能力打包为年度服务版，提高复购和运维收入。
4. 将低空巡查、视频提示和专题报告作为增强模块。
5. 将真实脱敏案例沉淀为课程包，服务职业院校和培训机构。

### 13.2 年度路线

第2年再往 10-20 个客户或合作点位走，补上年度服务体系、运维规范、权限体系、运营报告模板和低空巡查增强包。重点看复购、运维效率和收入稳不稳。

第3年进入区域复制阶段，扩到多点位文旅街区、夜市商圈、安保企业和职业院校。重点看标准产品、增强模块和课程服务能不能形成稳定收入。

## 十四、团队与组织分工

项目团队建议采用“产品场景 + 技术研发 + 低空应用 + 商业运营 + 合规财务”的组织结构。

| 角色 | 职责 |
|---|---|
| 项目负责人 | 统筹项目进度、资源对接、路演汇报和试点推进 |
| 产品与警务场景组 | 梳理夜市场景、事件分类、处置流程和训练脚本 |
| 前端研发组 | 负责小程序群众端、巡防端和 Web 指挥后台 |
| 后端与数据组 | 负责 API、数据库、权限、审计、报表和系统部署 |
| 低空巡查组 | 负责无人机巡查方案、图传协同和飞行合规边界 |
| 商业与运营组 | 负责客户访谈、试点沟通、报价体系和运营报告 |
| 合规与财务组 | 负责隐私保护、数据安全、合同材料和财务测算 |

团队优势可以按实际分工来写：场景侧懂治安和处置流程，技术侧负责研发和数据安全，低空侧负责机动巡查，法务侧盯证据固定和合规留痕，商务和财务侧负责计划书、报价和后续经营。

## 十五、风险控制

| 风险类型 | 具体表现 | 应对措施 |
|---|---|---|
| 场景验证风险 | 真实点位、人员和事件数据不足 | 先做样板试点，补齐访谈、演练和试运行记录 |
| 技术稳定风险 | 实时同步、定位、地图和消息通知存在兼容问题 | 建立测试清单，分端验证微信端、Web 端和后端接口 |
| 数据安全风险 | 位置、联系方式、现场照片和事件记录涉及隐私 | 最小必要采集、角色权限、脱敏展示、日志审计 |
| 低空应用风险 | 无人机飞行受天气、空域、场地和审批影响 | 以合规授权为前提，提供手动演示、模拟数据和替代方案 |
| 商业落地风险 | 客户预算周期长，试点转化不稳定 | 采用低门槛试点包，联合安保企业和学校实训场景切入 |
| 运营交付风险 | 现场培训、运维响应和客户支持成本上升 | 标准化部署手册、培训材料、远程运维和分级服务 |

## 十六、预期成果

项目预期形成以下成果：

- 一套可运行的烟火哨兵系统原型，包括小程序、巡防端、Web 指挥后台和后端服务。
- 一套夜市重点网格、事件类型、联动点位和处置流程标准。
- 一套事件流转台账，包括事件工单、报警推送、人员派单、路线推荐和审计日志。
- 一套面向项目申报和路演展示的演示脚本、截图、视频和讲解材料。
- 一套面向试点单位的部署方案、培训手册、运维清单和运营报告模板。
- 一套面向职业院校和安保培训的实训课程包、案例库和评分规则。

建议量化指标如下：

| 指标 | 原型阶段 | 试点阶段 | 产品阶段 |
|---|---:|---:|---:|
| 事件处理完成率 | 80%以上演示完成 | 90%以上试点完成 | 95%以上稳定完成 |
| 工单状态同步时延 | 20秒内 | 10秒内 | 5秒内 |
| 高风险事件派单时间 | 3分钟内 | 2分钟内 | 1分钟内 |
| 试点点位数量 | 1-2个 | 3-5个 | 10个以上 |
| 训练案例数量 | 10个 | 30个 | 100个以上 |
| 运营报告产出 | 月度样例 | 月度正式报告 | 自动化专题报告 |

以上指标在原型阶段可作为目标口径，进入真实试点后应以实际运行数据替换。

## 十七、材料补齐清单

为了让计划书更适合参赛、申报和对外合作，建议继续补齐以下材料：

- 调研材料：游客、商户、巡防人员、文旅运营方、安保企业和教师专家访谈。
- 点位材料：夜市核心网格图、入口出口、亲水区域、联动点、停车点和高发风险点。
- 案例材料：至少 8 类典型事件，每类包含苗头、风险、处置、结果和复盘。
- 产品材料：小程序求助、隐患上报、巡防接单、指挥派单、后台运行、事件截图。
- 试点材料：合作意向、指导意见、演练记录、试运行截图、用户反馈和改进记录。
- 合规材料：隐私说明、数据字段清单、权限分级、脱敏规则、低空巡查合规说明。
- 财务材料：报价单、成本明细、现金流测算、资金用途和阶段性收入证明。

## 十八、结语

烟火哨兵的核心价值，是把夜市夜间安全治理从分散响应推进到协同处理。它以群众求助和商户上报为入口，以巡防人员和指挥后台为处置抓手，以后端事件库和审计日志为数据底座，以辅助分析和低空巡查为增强能力，最终沉淀为可复盘、可训练、可复制的安全治理产品。

项目当前已经具备原型基础，下一步应围绕真实点位、真实角色、真实流程和真实试点持续补强。只要把产品演示、场景证据、运营指标和合作材料逐步补齐，烟火哨兵就可以从一个可运行原型，成长为面向滨江文旅、夜市商圈、安保企业和职业院校的综合性安全治理解决方案。
