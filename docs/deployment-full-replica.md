# 小安智能预警系统：完整 Windows 原生部署说明

本文面向部署负责人和维护人员，解释完整恢复会复制哪些内容、如何验证，以及哪些外部条件不能由文件迁移替代。部署路径为 Windows 原生运行，不使用 Docker Desktop。

## 架构和端口

| 组件 | 本机地址 | 用途 |
| --- | --- | --- |
| PostgreSQL 18 | `127.0.0.1:5433` | 独立业务数据库 |
| FastAPI | `127.0.0.1:8010` | 业务 API、鉴权、设备桥接和告警写入 |
| 管理网页 | `127.0.0.1:8080` | 小安管理和指挥页面 |
| Java 检测服务 | `127.0.0.1:5000` | 摄像头、检测、训练管理、go2rtc 协调 |
| go2rtc | `127.0.0.1:1984/8554/8555` | 仅供本机检测服务使用的转流端口 |

所有入口仅绑定 `127.0.0.1`。若要让其他电脑访问，必须由维护人员另行配置受控的 HTTPS 反向代理、访问控制和防火墙；本仓库不会把数据库、摄像头或管理 API 直接暴露到局域网或公网。

## 仓库和私有迁移材料的边界

GitHub 仓库应包含：应用源码、构建文件、Windows 原生启动脚本、测试、公开模型文件和无凭据的 go2rtc 程序。

GitHub 仓库绝不能包含：`.xiaoan` 迁移包、`.transfer-key` 密钥、`deploy/native/*.env`、运行日志、PostgreSQL 数据目录、账号报告、设备凭据、证据媒体、训练数据、恢复后的检测数据或任何云端密钥。

完整迁移需要三类独立物料：

1. 与迁移包版本配套的代码文件夹。
2. 加密迁移包 `.xiaoan`。
3. 单独保管的配对密钥 `.transfer-key`。

不要混用不同来源的迁移包和密钥。恢复程序通过认证加密检查包完整性，随后检查数据库表/行数和每个恢复文件的 SHA-256。

## 首次完整恢复的流程

1. 在目标电脑解压新的代码目录。目标目录不得存在 `deploy/native/.env`、`deploy/native/data`、`deploy/native/.runtime` 或之前恢复的私有数据。
2. 运行 `install-prerequisites.cmd`。脚本检查 Python 3.12、Java 21、PostgreSQL 18，并准备 Node.js 22。
3. 运行 `restore.cmd`，在两个文件选择窗口中分别选择迁移包和密钥。
4. 脚本创建目标部署专用配置、PostgreSQL 数据目录和私有临时目录；已有配置或非空数据目录会被拒绝。
5. 脚本认证解密迁移包，使用 `pg_restore --single-transaction --exit-on-error` 恢复 PostgreSQL。
6. 脚本恢复证据、设备桥接资料、检测数据、检测配置、模型、训练数据和训练结果到原生目录。
7. 脚本核对文件列表、文件大小、SHA-256、数据库表名和每张表的行数。
8. 脚本创建或验证目标部署专用的业务账号报告和检测上报服务密钥；密钥只写入受保护的私有目录和私有环境文件。
9. 脚本启动 API、检测服务和管理网页，并等待健康检查通过。

恢复失败时不要在原目录继续尝试，更不要手工删除数据库文件或私有配置。保留错误现场，重新解压新的代码目录后再尝试。

| 范围 | 恢复位置 | 校验方式 |

| 事件证据 | `server/data/event-evidence` | 文件清单、大小、SHA-256 |
| 设备桥接加密资料 | `server/.secrets/device-bridges` | 文件清单、大小、SHA-256 |
| 视频检测数据 | `server/security-data` | 文件清单、大小、SHA-256 |
| 检测服务数据 | `integrations/detector/server/data` | 文件清单、大小、SHA-256 |
| 检测配置和摄像头配置 | `integrations/detector/runtime` | 文件清单、大小、SHA-256 |
| 检测模型 | `integrations/detector/models` | 文件清单、大小、SHA-256 |
| 检测结果 | `integrations/detector/results` | 文件清单、大小、SHA-256 |
| 训练数据集 | `integrations/detector/detection/datasets` | 文件清单、大小、SHA-256 |
| 训练运行结果 | `integrations/detector/runs` | 文件清单、大小、SHA-256 |

若某一目录在迁移包中为空，恢复后相应目录也为空；脚本不会凭空生成原系统没有的数据。

## 运行目录和维护命令

| 文件或目录 | 作用 | 是否可上传 |
| --- | --- | --- |
| `start.cmd` | 启动原生服务 | 可以 |
| `stop.cmd` | 停止本项目服务，保留数据 | 可以 |
| `enable-cameras.cmd` | 在确认硬件后启用桥接、检测和转流 | 可以 |
| `restore.cmd` | 在新代码目录恢复加密迁移包 | 可以 |
| `deploy/native/.env` | 数据库密码、端口和本机控制项 | 不可以 |
| `deploy/native/runtime.env` | 恢复的 API 私有配置 | 不可以 |
| `deploy/native/detector.env` | 检测端账号和上报密钥 | 不可以 |
| `deploy/native/data`、`.runtime`、`logs`、`run` | 本机数据库、依赖缓存、日志和 PID | 不可以 |

启动日志在 `deploy/native/logs`。遇到问题只向受信任维护人员提供最少、已经审查过的日志片段；日志可能包含业务路径或运行信息。

## 摄像头和检测安全开关

恢复和常规启动默认使用：

```text
CICSIC_BRIDGE_AUTOSTART=false
DETECTOR_AUTOSTART=false
GO2RTC_AUTOSTART=false
```

这意味着设备资料已恢复，但不会自动连接真实摄像头、USB 相机或机器人。确认设备网络、驱动、账号和现场授权后，运行 `enable-cameras.cmd` 才会把三个开关改为启用状态并重启服务。

若要停用硬件采集，执行 `stop.cmd` 后用文本编辑器将以上三项改回 `false`，再运行 `start.cmd`。不要把设备密码、RTSP 地址或密钥写入公开文档、截图或 Git 提交。

## 验收清单

完成完整恢复后，维护人员应逐项确认：

1. `http://127.0.0.1:8080` 能打开主系统和深层页面。
2. `http://127.0.0.1:8010/api/health/ready` 返回 `ready` 且数据库引擎为 `postgresql`。
3. `http://127.0.0.1:5000/api/detection/status` 可访问。
4. 恢复窗口明确显示数据库和文件校验通过。
5. 在隔离测试中读取一条已恢复的事件、证据附件、设备配置和检测记录。
6. 仅在受控网络中启用摄像头后，逐台验证视频连通、解码、检测上报和断线重连。
7. 使用 `stop.cmd` 后再使用 `start.cmd`，确认数据仍保留。

本地健康检查、构建成功或文件存在都不能替代真实摄像头、机器人、USB、设备网络和外部平台的现场验收。

## 外部依赖和已知边界

以下事项必须在目标环境另行配置或验收：摄像头/NVR/机器人网络、USB 驱动、厂商账号和授权、微信或支付宝小程序 AppID 与域名、地图服务密钥、视觉模型或云 AI 服务额度、HTTPS 证书、公网/局域网访问策略，以及迁移包中没有的本地模型。

小程序源码包含在仓库内，但正式发布到微信或支付宝还需要该平台自己的开发者账号、AppID、域名校验和真机验收。迁移包恢复成功不等于第三方平台发布成功。

## 后续备份

恢复后的新业务数据不会自动写回原迁移包。下一次迁移前，应在受控环境中重新制作数据库逻辑备份、私有文件快照和新的加密迁移包，并在另一份新代码目录中完成恢复验证。不要把 `deploy/native` 的私有配置、数据库目录或运行缓存当作可公开发布的备份。
