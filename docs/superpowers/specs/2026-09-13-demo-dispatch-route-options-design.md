# 脱敏警力调度多路线设计

## 目标

在 `/command` 的脱敏警力地图中展示多个小路口和多条可达路线，并明确标出系统自动推荐的最优路线。同时展示一处位于非推荐路线上的拥堵路段，帮助用户理解系统为什么选择当前路线。

## 约束

- 页面继续使用完全虚构的地图底图，不加载高德、百度或其他真实地图服务。
- 不使用真实地名、真实经纬度、真实警力位置或外部地图 URL。
- 保留现有的报警处、3 个警力点、5 公里态势范围、北向指示和 1 公里比例尺。
- 不恢复已删除的通勤推荐、右侧调度面板、流程表单或确认按钮。
- 视图需要适配当前约 529px 宽的窄屏浏览器。

## 设计

### 视觉层级

- 底图增加更多支路、交叉口和街区连接，形成可理解的虚构路网。
- 2 至 3 条候选路线使用低对比度灰蓝细线。
- 最近警力到报警处的最优路线使用蓝色实线，并显示“系统推荐”标签。
- 一条非推荐候选路线局部使用橙红色覆盖线，并显示“前方拥堵”标识。
- 图例增加“候选路线”“系统推荐”“拥堵路段”，保持地图底部信息简洁。

### 数据与组件

扩展 `DemoDispatchData`：

- `routeOptions`：候选路线数组，每条包含 id、路线点、状态和可选的拥堵段。
- `recommendedRouteId`：系统推荐路线 id。
- `congestion`：拥堵提示的画布位置、文案和关联路线 id。

`DemoDispatchMap` 根据数据渲染：

1. 候选路线；
2. 推荐路线高亮；
3. 拥堵路段覆盖；
4. 推荐和拥堵标签；
5. 现有报警处与警力点。

原有 `routePoints` 可作为兼容字段保留，或由推荐路线统一取值，但组件只应维护一个实际推荐路线来源。

## 交互与响应式

- 本次不增加地图缩放、拖拽或路线切换交互。
- 推荐路线和拥堵状态是静态脱敏演示数据。
- 标签靠近左右边界时自动调整展开方向，避免窄屏裁切。
- `prefers-reduced-motion` 下不增加新的动画。

## 测试与验收

- 单元/源码测试验证存在多条候选路线、推荐路线和拥堵状态。
- 测试继续禁止 `AMap`、`amap`、`latitude`、`longitude`、高德、百度和真实地名。
- TypeScript 检查通过。
- Vite 生产构建通过。
- 浏览器窄屏检查确认：
  - 至少 3 条路线清晰可见；
  - 蓝色路线明显是系统推荐；
  - 拥堵提示位于非推荐路线；
  - 点位和标签未被裁切。
