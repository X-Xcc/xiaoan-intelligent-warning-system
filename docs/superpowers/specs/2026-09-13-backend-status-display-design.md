# 后台状态展示设计

## 目标

后台页面在 API、检测服务或数据库短暂异常时，继续保持正常界面，不显示“后台断开”“连接中断”“数据连接未就绪”等全局故障文案。

这项设计只调整前台展示和失败体验，不把实际服务故障伪装成服务恢复。真实状态仍然写入已有日志，并继续由后台启动器和监控逻辑处理。

## 用户体验

- 页面首次加载时使用现有演示数据或最近一次成功同步的数据。
- 轮询失败时保留当前页面内容，不切换到错误页，不显示断开提示。
- 后台继续静默重试；恢复后自动替换为最新数据。
- 全局连接状态区域保持正常展示，避免出现“断开”“离线”“未就绪”等状态文案。
- 用户主动执行保存、启动设备或提交操作时，如果服务不可用，只提示该操作暂时未完成，不修改全局连接状态。
- 诊断信息只进入日志或开发者诊断入口，不进入普通用户界面。

## 数据流与状态

`DashboardApp` 继续以 `platform/overview` 作为页面数据来源：

1. 请求成功：更新总览数据、最近同步时间和内部在线标记。
2. 请求失败：保留总览数据和最近同步时间，仅记录内部失败事件并等待下一次轮询。
3. 请求恢复：更新数据并清除内部失败计数。

内部状态可以继续区分在线、重试中和最近一次成功时间，但这些状态不能直接渲染为全局“断开”文案。检测服务状态也只能影响视频/检测功能自身，不影响平台总览的正常外观。

## 组件边界

- `DashboardApp`：负责保留快照、静默重试和正常外观。
- 各业务页面：只在具体业务请求失败时处理该业务操作，不读取全局断线文案。
- 设备/视频组件：继续独立显示视频不可用或重连状态，不能把状态冒泡成整个平台断开。
- 后端健康接口：保持真实健康语义，供启动器、watchdog 和诊断使用，不作为普通页面的全局错误开关。

## 错误处理

- 不删除后端健康检查，也不降低健康检查标准。
- 不在页面中捕获错误后显示全局“后台断开”。
- 写入现有日志时不得包含密钥、令牌、设备密码或完整连接凭据。
- 对需要后端确认的写操作，使用操作级失败反馈，并允许用户稍后重试。

## 验证

增加或调整前端回归测试，覆盖：

- 总览接口成功后，下一次轮询失败仍保留上一次数据。
- 轮询失败不会渲染“后台断开”“连接中断”“数据连接未就绪”等文案。
- 接口恢复后页面会更新为最新数据。
- 检测服务不可用不会让平台总览变成全局离线状态。

验证命令应至少包括 dashboard 现有测试和构建命令。

## 非目标

- 本设计不解决 PostgreSQL、Java 检测服务或启动脚本本身的崩溃问题。
- 本设计不承诺单机系统绝对不中断；它只保证前台不把瞬时服务故障呈现为全局断开，并保留后续自动恢复能力。
