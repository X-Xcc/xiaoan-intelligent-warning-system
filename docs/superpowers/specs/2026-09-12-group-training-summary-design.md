# 三人三科目训练演示流程设计

## 目标

将勤务训练演示从“单人单科目分别完成评分和归档”调整为“一次固定三人小组训练演示”：

`单警装备快速取用 → 弱光执法场景战术协同 → 防爆先期处置 → 总结评分`

演示结束时只生成三名参训人员各自一个训练总分，并自动生成每个人的优点和缺点。

## 范围

- 仅调整 dashboard 中的演示训练工作区。
- 复用现有演示数据中的三名人员：`DEMO-OFFICER-017`、`DEMO-OFFICER-018`、`DEMO-OFFICER-019`。
- 复用现有前三个训练科目及训练记录能力。
- 不设计或引入真实训练业务的持久化小组模型。
- 不展示也不调用教官复核、单科目评分、训练档案和补训流程。

## 用户流程

### 进入演示

从勤务态势推荐进入第一个科目后，页面进入固定三人小组模式。小组成员在本次流程内固定，不提供按人员切换。

### 科目流程

每个科目都包含两个页面阶段：

1. 科目建议：展示当前科目的训练目标、训练安排、完成检查和安全提示。
2. 训练记录：展示当前科目的演示训练记录区域。

点击“下一步”时：

- 第一个科目完成后，进入第二个科目的科目建议。
- 第二个科目完成后，进入第三个科目的科目建议。
- 第三个科目完成后，进入总结评分。

页面进度只表达当前科目和阶段，不再出现“考核复核”和“训练档案”步骤。

### 总结评分

总结页展示三名参训人员，每人一条总结结果：

- 人员姓名或演示人员标识；
- 一个 0 至 100 的训练总分；
- 自动生成的优点；
- 自动生成的缺点。

不展示三项科目的分数，不提供教官评分输入框，不提供复核人、复核意见、归档或补训按钮。

## 演示数据和评分

- 总结内容使用确定性的演示数据，刷新或重复演示时结果稳定。
- 总分可基于三项训练记录的内部演示结果计算，但只向用户展示每个人的最终总分。
- 优点和缺点由前端根据演示总分及三项训练完成状态生成，不需要用户填写。
- 三人总结结果只服务于当前演示工作区；不写入训练档案。
- 现有历史 assessment/archive 数据即使仍被底层快照读取，也不得进入新的页面展示或流程判断。

## 状态和数据流

前端新增一个轻量的演示小组流程状态，至少包含：

- 固定成员列表；
- 固定科目列表及当前科目索引；
- 当前阶段：`prepare` 或 `run`；
- 已完成科目集合；
- 总结结果生成状态。

训练记录阶段可以继续复用现有演示任务的开始、完成动作，或使用同等的演示本地状态推进，但不得触发 assessment、review、archive 或 retraining 请求。

现有单人任务列表、人员切换、个人档案列表和历史档案入口不属于新流程的用户界面。若为兼容既有演示数据而保留底层类型或接口，不改变新流程的可见行为。

## 页面结构

- 顶部显示训练演示标题、三名参训人员和整体进度。
- 主内容显示当前科目的建议或训练记录。
- 底部只保留“上一步”和“下一步”；总结页提供“完成演示”。
- 删除或隐藏个人任务筛选、个人档案入口、考核复核表单、单科目评分卡、档案详情和补训入口。

## 错误处理

- 演示数据加载失败时保留现有错误提示和重新同步能力。
- 当前科目推进失败时停留在当前阶段，不提前切换到下一科目。
- 总结生成失败时保留当前训练完成状态，并允许重新生成。
- 页面卸载或重新进入时不得产生重复的 summary 结果或重复的业务写入。

## 验证标准

自动化验证至少覆盖：

- 进入第一个科目后显示“科目建议”；
- 第一个和第二个科目的下一步按顺序进入下一个科目；
- 第三个科目下一步进入总结评分；
- 总结页正好显示三名人员、每人一个总分、优点和缺点；
- 页面中不存在教官复核、单项评分、训练档案和补训入口；
- 不发送 assessment、review、archive 或 retraining 请求；
- 桌面端、浏览器中等宽度、390px 移动端和 320px 小屏无横向溢出、无文字遮挡；
- 刷新或重新进入不会重复生成总结结果。
