# 训练页 02 路机械狗热成像演示设计

## 目标

将训练页 `/duty-situation/training` 的 02 路监控替换为一个纯前端的机械狗热成像演示画面。该画面只用于演示，不连接真实 Go2、不读取真实设备绑定，也不启动视频桥接服务。

## 用户体验

- 02 路标题显示“机械狗热成像”。
- 监控区域保持训练页现有 16:9 比例、放大按钮和刷新按钮。
- 画面使用暗色热成像伪彩背景，显示机械狗轮廓、扫描线和轻微热源呼吸动画。
- 画面角标显示“机械狗巡检视角 · 热成像”和演示状态。
- 03 路监控行为保持现状，不受演示画面影响。
- 02 路刷新按钮只重置演示画面的动画时间，不发起设备服务请求。
- 放大对话框中继续显示同一份演示画面。

## 方案

在 `TrainingCameraPreview` 中为 02 路增加明确的演示 feed 分支。演示 feed 使用独立的 React 组件和 CSS 动画，不复用 `BridgePreview`，避免误触真实设备 API。

数据流如下：

1. 训练页渲染双路监控。
2. 02 路进入 `FakeThermalMonitor`，仅使用本地状态和 CSS。
3. 03 路继续根据现有设备桥接清单读取 `bindings[2]` 并渲染 `BridgePreview`。
4. 02 路放大时复用 `FakeThermalMonitor`，刷新时递增本地 key 以重置动画。

不修改后端设备桥接、Go2 驱动、视频槽位持久化或真实视频墙。

## 性能与降级

- 动画仅使用 CSS `transform`、`opacity` 和一个固定尺寸伪彩层，避免 Canvas 高频重绘。
- 不新增网络请求、视频解码或图片轮询。
- `prefers-reduced-motion: reduce` 下关闭扫描和呼吸动画，保留静态热成像画面。
- 组件不依赖外部图片文件，避免资源加载失败。

## 测试

- 更新训练监控组件测试，验证 02 路不读取 `bindings[1]`，而是渲染本地演示组件。
- 验证 03 路仍读取 `bindings[2]`。
- 验证 02 路刷新与放大只影响演示组件，不调用 `bridge.refresh()`。
- 运行 dashboard 现有测试与生产构建。
- 在桌面训练页和窄屏布局中检查 02 路画面不溢出、放大对话框可用。
