# 接触记录检索工作台设计

## 目标

在公安大数据与 AI 平台中增加一个“接触记录检索”页面：用户上传或选择一个检索对象照片后，按近一个月的时间范围筛选已接入的监控记录，查看记录时间、地点、同行对象的已有登记信息，并由人工决定哪些记录进入后续核验。

## 边界

- 页面只展示数据源已经提供的时间、地点、摄像头编号和登记档案字段。
- 不使用人脸相似度推断身份，不从姿态、表情或聊天动作判断“密谋”“涉案”或其他罪责。
- AI 只作为“排序建议”占位，建议必须人工复核；演示数据明确标注为脱敏样例。
- 用户提供的人像仅作为本地检索对象预览，不上传到外部图像服务。
- 演示记录使用项目现有监控素材和虚构档案字段，不把真实人物合成进新的场景。

## 页面结构

- 左侧：检索对象卡片、上传入口、时间范围、地点、记录状态筛选和“开始检索”按钮。
- 中间：结果数量、排序建议说明、时间线式照片网格；每条记录包含时间、地点、摄像头、同行对象编号、人工复核状态。
- 右侧：选中记录的大图、记录元数据、同行对象的“已有登记信息/未提供”字段、人工备注、加入复核清单按钮。
- 页面顶部：标题、演示数据状态、最近同步时间和返回平台总览入口。

## 数据与交互

- 默认时间范围为最近 30 天，默认载入 20 条脱敏样例记录。
- 20 条样例记录均展示同一检索对象的已确认命中结果；同行对象为虚构编号，其中一个编号重复出现，其余为不同编号。
- “高相关”仅表示规则排序结果，不使用“嫌疑”“密谋”等定性标签。
- 支持搜索地点、摄像头和同行对象编号；支持状态筛选：全部、待复核、已标记、已排除。
- 点击照片更新右侧详情；可标记、排除、添加备注；刷新后保留当前页面的本地交互状态。
- 没有档案来源的同行对象字段显示“未提供”，不自动补全姓名、职业或关系。

## 路由与实现

- 新增路由 `/contact-review`，加入现有平台侧栏“业务工作台”。
- 新增 `ContactReviewPage.tsx` 和 `contact-review.css`，继续使用现有 React、Ant Design、Lucide 和平台样式变量。
- 在 `DashboardApp.tsx` 和 `presentation.ts` 中注册路由、导航项和页面分发。
- 演示数据放在页面模块的纯数据常量中，图片复用 `public` 下现有监控素材。

## 验收

- `npm run dashboard:build` 成功。
- 路由可从侧栏进入，桌面端三栏布局不重叠，小屏幕可纵向浏览。
- 上传控件、时间/地点/状态筛选、关键词检索、照片选择、标记/排除和备注均可操作。
- 页面明确显示“脱敏演示数据/非真实证据”和“AI 排序建议需人工复核”。
- 不出现外部 API key、真实人物合成素材或未经来源支持的身份信息。
