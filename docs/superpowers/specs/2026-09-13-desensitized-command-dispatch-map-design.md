# 脱敏警力调度地图设计

## 背景

接处警现场页点击“下一步”后，需要进入一个更专业的警力调度视图，展示附近警力、最近警力前往路线以及推荐通勤方式。

该系统用于演示和培训。页面不得呈现真实地图、真实地名、真实道路、真实经纬度或可推断真实位置的警力数据。

## 目标

- 点击“下一步”后进入独立的警力调度页。
- 以完全虚构的网格态势图展示警情点、附近警力点和推荐路线。
- 展示最近警力的距离、预计到达时间、状态和推荐通勤方式。
- 保持与现有小安智能预警系统一致的蓝白色工作台视觉语言。
- 明确标注脱敏演示属性，不触发真实派警。
- 为未来替换为真实数据保留清晰的数据边界，但本次不接入地图服务。

## 非目标

- 不接入高德、百度、腾讯或其他地图 SDK。
- 不读取或显示真实经纬度。
- 不使用现有真实城市地图、卫星图、道路图或真实行政区名称。
- 不实现真实导航、实时定位、真实警力派遣或外部通信。
- 不修改现有接处警业务流程之外的页面。

## 方案

采用独立的“警力调度”页面和本地演示数据模型。地图区域使用纯本地绘制的虚构网格图，不依赖网络资源和地图密钥。页面通过路由状态携带当前警情上下文，调度页从脱敏演示数据中解析当前警情、警力和路线。

### 页面结构

1. 页面头部
   - 标题：警力调度
   - 警情编号、虚构区域、风险等级、当前状态
   - 脱敏提示：脱敏演示数据 · 不对应真实地理位置 · 未执行真实派警

2. 地图态势区
   - 虚构网格：演示辖区、A 区、B 区、主街、北侧入口等
   - 红色警情点：当前事件位置
   - 蓝色警力点：附近在线警力
   - 高亮路线：最近警力到虚构警情点的推荐路线
   - 图例、缩放、回到警情点等本地交互控件

3. 调度信息区
   - 最近警力卡片：编组名称、距离、预计到达时间、当前任务状态
   - 推荐通勤方式列表：警车、摩托车、步行等本地演示选项
   - 当前推荐方案：例如“快反组 01，摩托车至北侧入口后步行”
   - 调度操作：确认演示派警、返回现场核查

4. 流程区
   - 警情确认
   - 警力匹配
   - 路线推荐
   - 派警确认

### 数据模型

调度页只消费脱敏模型，不消费真实地理字段：

```ts
type DemoDispatchPoint = {
  id: string;
  label: string;
  x: number;
  y: number;
  status: 'incident' | 'available' | 'busy';
};

type DemoDispatchUnit = {
  id: string;
  name: string;
  role: string;
  status: '可调度' | '处置中' | '已离线';
  distanceLabel: string;
  etaLabel: string;
  pointId: string;
};

type DemoCommuteOption = {
  id: string;
  label: string;
  detail: string;
  distanceLabel: string;
  etaLabel: string;
  recommended?: boolean;
};
```

坐标仅表示虚构画布中的百分比位置，字段名和文案不得暗示经纬度。演示数据固定在前端本地模块中，便于测试和截图复现。

### 路由与状态

- 现场页的“下一步”调用父级导航回调，进入独立的 `command-workbench` 路由或当前项目等价的调度子路由。
- 调度页通过当前警情 ID 读取对应的本地脱敏演示数据。
- “确认演示派警”只更新本地 UI 状态并显示确认反馈，不调用后端派警接口。
- “返回现场核查”返回现场页，不丢失当前警情上下文。
- 浏览器刷新后仍能根据路由恢复调度页的默认演示状态。

### 视觉与交互

- 继续使用现有 `foundation.css` 的颜色、边框、字号和按钮规范。
- 地图是一个稳定比例的本地绘图区，使用道路、网格和区域标签构成，不使用真实地图图片。
- 路线使用本地绘制的折线或路径层，警情点和警力点使用可读的图例与状态颜色。
- 所有图标继续使用 `lucide-react`。
- 按钮、标记和调度选项具备键盘焦点、可读标签和明确的 hover/pressed 状态。
- 移动端采用地图在上、调度面板在下的单列布局。

### 错误与降级

- 找不到警情 ID 时，使用通用脱敏演示警情，并在页面上显示“演示数据”状态。
- 不允许因为地图密钥缺失、网络不可用或外部脚本失败而进入错误态；页面完全依赖本地资源。
- 若本地演示数据不完整，显示“待补充演示信息”，不拼接真实数据作为兜底。
- 确认按钮在本地状态更新前保持可用，确认后变为“已确认演示派警”，避免暗示真实执行。

## 组件边界

- `CommandScene`：负责现场处置页，触发下一步导航。
- `CommandDispatchPage`：负责调度页面布局和本地调度状态。
- `DemoDispatchMap`：只负责渲染虚构网格、标记、图例和路线，不依赖地图 SDK。
- `demo-dispatch-data.ts`：集中保存脱敏演示点位、警力和通勤方式。
- `command-dispatch.css`：调度页面专属样式，复用全局设计 token。

组件之间通过显式 props 传递当前警情和选中警力，地图组件不直接读取路由或后端数据。

## 测试策略

- 为演示数据解析增加单元测试，确认没有经纬度字段、真实地名或外部地图 URL。
- 为调度页增加组件级测试，确认：
  - 页面展示脱敏声明。
  - 警情点、至少两个警力点和推荐路线可见。
  - 最近警力与推荐通勤方式信息可见。
  - 确认演示派警只改变本地状态。
  - 缺失警情 ID 时回退到通用脱敏数据。
- 运行现有 dashboard 测试和 TypeScript 构建。
- 使用浏览器验证 `/command` 点击“下一步”后的路由、桌面布局和移动端单列布局。
- 检查页面网络请求，确认调度页不请求地图 SDK 或外部地图资源。

## 验收标准

- 点击现场页“下一步”后能看到独立调度页。
- 页面中不存在真实地图、真实地名、真实经纬度或真实警力数据。
- 地图区域能清楚表达警情点、附近警力分布和最近警力路线。
- 右侧或下方能看到至少三种推荐通勤方式及一条明确推荐。
- “确认演示派警”有可见的本地确认反馈，且不触发真实派警接口。
- 页面在当前工作台视觉体系下保持专业、可扫描、可操作。
